5. SQL & Bancos de Dados

O que é um banco relacional

Antes de escrever qualquer comando SQL, entenda o que é um banco de dados, por que ele existe e como ele organiza informação.

Analogia Imagine um consultório médico antigo, daqueles com um armário cheio de gavetas. Cada gaveta é rotulada ("Pacientes", "Consultas", "Convênios") e dentro de cada gaveta existem fichas de papel padronizadas: toda ficha de "Pacientes" tem os mesmos campos — nome, data de nascimento, telefone — só que preenchidos com valores diferentes para cada pessoa. Um banco de dados relacional é exatamente esse armário, só que organizado por um computador: as "gavetas" são as tabelas, e as "fichas" dentro de cada gaveta são as linhas.

Um banco de dados é, de forma simples, um sistema especializado em guardar, organizar e buscar informação de forma confiável e rápida — mesmo quando essa informação cresce para milhões de registros e é acessada por milhares de pessoas ao mesmo tempo. Um banco de dados relacional (os mais usados no mundo — MySQL, PostgreSQL, SQL Server, SQLite) organiza tudo em tabelas que podem se relacionar entre si, e usa uma linguagem chamada SQL (Structured Query Language) para ler e escrever essas informações.

Por que não usar uma planilha de Excel ou um arquivo de texto?

É uma pergunta justa: se uma planilha também tem linhas e colunas, por que não usar só ela para o sistema de uma empresa inteira? A resposta é que planilhas e arquivos de texto funcionam bem para poucos dados e pouca gente mexendo neles, mas quebram rapidamente em cenários reais:

  • Concorrência. Se duas pessoas abrirem o mesmo arquivo Excel ao mesmo tempo e salvarem, uma sobrescreve o trabalho da outra. Um banco de dados foi desenhado para centenas de pessoas lerem e escreverem ao mesmo tempo, sem conflito.
  • Integridade. Nada impede que alguém digite "trinta reais" numa célula que devia ter um número, ou deixe um campo obrigatório em branco. Um banco de dados pode forçar regras: "este campo é sempre obrigatório", "este valor tem que ser um número", "este e-mail não pode se repetir".
  • Velocidade em grande escala. Procurar um cliente específico entre 50 linhas de Excel é rápido de qualquer jeito; procurar entre 20 milhões de linhas exige estruturas de busca eficientes, que é justamente a especialidade de um banco de dados (vamos ver isso na lição sobre índices).
  • Relacionamentos sem repetição. Numa planilha única, para cada pedido você repetiria o nome e o endereço completo do cliente em todas as linhas. Isso desperdiça espaço e, pior: se o cliente mudar de endereço, você precisa corrigir em todas as linhas onde ele aparece, ou os dados ficam inconsistentes. Bancos relacionais resolvem isso separando a informação em tabelas conectadas.
Dica Não existe problema em usar uma planilha para organizar sua lista de compras ou o orçamento pessoal. O banco de dados relacional entra em cena quando o volume de dados cresce, quando várias pessoas (ou vários sistemas) precisam acessar as mesmas informações ao mesmo tempo, e quando é fundamental que os dados nunca fiquem inconsistentes.

Tabela, linha e coluna

Dentro de um banco relacional, cada "gaveta" da nossa analogia é uma tabela. Uma tabela guarda um tipo de coisa — clientes, produtos, pedidos — e tem uma estrutura fixa de campos, chamados colunas. Cada registro individual dentro da tabela é uma linha (também chamada de "registro" ou "tupla").

Veja uma tabela simples chamada clientes:

idnomeemailcidade
1Ana Souzaana@email.comRecife
2Bruno Limabruno@email.comCuritiba
3Carla Diascarla@email.comSão Paulo

Aqui, id, nome, email e cidade são as colunas — elas definem quais informações cada cliente vai ter. Cada linha (1, 2, 3) é um cliente específico, com um valor preenchido em cada coluna. Todo cliente cadastrado segue exatamente essa mesma estrutura, assim como toda ficha de papel do armário segue o mesmo modelo.

Chave primária: o "RG" de cada linha

Repare na coluna id da tabela acima. Ela existe para resolver um problema: nomes se repetem, e-mails podem mudar, cidades são iguais para várias pessoas — mas precisamos de uma forma garantida de apontar para "este cliente específico e nenhum outro". Essa coluna especial é chamada de chave primária (primary key, ou PK): um valor único que identifica cada linha da tabela sem ambiguidade, assim como um RG ou CPF identifica uma pessoa de forma única no mundo real.

Duas regras acompanham a chave primária: ela nunca pode se repetir dentro da tabela, e nunca pode ficar vazia. Na prática, a maioria dos bancos de dados gera esse número automaticamente (1, 2, 3, 4...) sempre que uma nova linha é inserida, então você raramente precisa se preocupar em definir esse valor manualmente.

Chave estrangeira: a "cola" entre tabelas

Agora imagine uma segunda tabela, pedidos, guardando as compras feitas pelos clientes:

idprodutovalorcliente_id
1Teclado150.001
2Mouse60.001
3Monitor900.002

A coluna cliente_id não guarda um dado novo — ela guarda o id de uma linha da tabela clientes. É assim que as duas tabelas se conectam: o pedido 1 "aponta" para o cliente de id 1 (Ana Souza), o pedido 3 aponta para o cliente de id 2 (Bruno Lima). Essa coluna que aponta para a chave primária de outra tabela é chamada de chave estrangeira (foreign key, ou FK). É graças a esse mecanismo que conseguimos guardar o cliente uma única vez e ainda assim relacioná-lo com quantos pedidos ele fizer, sem duplicar o nome e o e-mail dele em cada linha de pedido.

Atenção Um erro comum de iniciante é tentar guardar "tudo numa tabela só" — por exemplo, repetir o nome e o e-mail do cliente em cada linha de pedido. Isso parece mais simples no começo, mas gera dados duplicados e abre espaço para inconsistência (e se o e-mail estiver escrito diferente em duas linhas do mesmo cliente?). Separar em tabelas relacionadas por chave primária/estrangeira é o coração do modelo relacional, e vamos aprofundar isso nas próximas lições sobre JOIN e normalização.

Onde o SQL entra nessa história

Depois que os dados estão organizados em tabelas, precisamos de uma forma de conversar com o banco: pedir para ele guardar um novo cliente, buscar todos os pedidos de uma pessoa, atualizar um endereço, apagar um registro antigo. Essa "língua" é o SQL, e ela é praticamente igual entre os principais bancos relacionais do mercado (PostgreSQL, MySQL, SQL Server, SQLite). Nas próximas lições desta trilha, você vai aprender os quatro comandos mais usados do SQL — SELECT, INSERT, UPDATE e DELETE — e, em seguida, como unir tabelas relacionadas usando JOIN.

Resumo

  • Um banco de dados relacional organiza informação em tabelas, e usa SQL para ler e escrever nelas.
  • Planilhas e arquivos de texto não escalam bem: faltam controle de concorrência, integridade e velocidade em grande volume.
  • Tabela = "gaveta" de um tipo de dado; coluna = campo fixo; linha = um registro individual.
  • Chave primária (PK) identifica cada linha de forma única e nunca se repete, como um RG.
  • Chave estrangeira (FK) é uma coluna que aponta para a PK de outra tabela, criando o relacionamento entre elas.
