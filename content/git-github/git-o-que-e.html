4. Git & GitHub

O que é controle de versão

Entenda o problema que o Git resolve antes de aprender qualquer comando.

Analogia Você já editou um trabalho da faculdade e, sem perceber, foi salvando arquivos assim: trabalho.docx, trabalho_final.docx, trabalho_final2.docx, trabalho_final_DEFINITIVO.docx, trabalho_final_DEFINITIVO_agora_vai.docx? O Git é a ferramenta que existe para você nunca mais precisar fazer isso. Em vez de criar cópias inteiras do arquivo com nomes cada vez mais desesperados, o Git guarda, de forma organizada, cada "versão" do seu projeto — como um álbum de fotos que registra exatamente como tudo estava em cada momento, permitindo voltar no tempo, comparar versões e entender quem mudou o quê e por quê.

Todo mundo que já trabalhou em algum arquivo importante — um documento, uma planilha, um projeto de código — já viveu o problema do "qual versão é a certa?". Sem uma ferramenta de controle de versão, as soluções costumam ser desesperadas: duplicar arquivos com nomes diferentes, mandar o arquivo por e-mail para "ter um backup", ou simplesmente torcer para não precisar desfazer nada. Isso funciona mal mesmo sozinho, e funciona muito pior quando várias pessoas mexem no mesmo projeto ao mesmo tempo.

O problema do "final_v2_definitivo.docx"

Imagine três colegas trabalhando juntos num mesmo documento. Cada um faz sua parte, salva uma cópia com um nome ligeiramente diferente e manda por e-mail. No fim do dia, alguém precisa juntar manualmente as mudanças de todo mundo, copiando e colando trechos, torcendo para não perder nada e sem nenhuma forma confiável de saber quem escreveu o quê. Se um erro aparecer depois, ninguém sabe exatamente quando ele foi introduzido nem como reverter só aquela mudança sem perder o resto do trabalho.

No mundo do desenvolvimento de software esse problema é ainda mais grave, porque um projeto pode ter milhares de arquivos de código, dezenas de pessoas mexendo neles todos os dias, e um único caractere errado pode quebrar o sistema inteiro. Foi para resolver exatamente isso que surgiram os sistemas de controle de versão — e o Git, criado em 2005 pelo mesmo Linus Torvalds que criou o Linux, é hoje o mais usado do mundo, de longe.

O que é um commit

Em vez de salvar um arquivo novo toda vez que você termina uma etapa, o Git te deixa registrar um commit: uma "fotografia" do estado exato do seu projeto naquele momento, acompanhada de uma mensagem explicando o que mudou. Pense em cada commit como um marco de um jogo salvo — você pode voltar para qualquer um deles quando quiser, comparar dois marcos diferentes para ver o que mudou entre eles, ou entender exatamente em qual momento um problema apareceu.

O importante é que o Git não guarda "arquivos com nomes diferentes" — ele guarda o histórico completo de mudanças de um mesmo conjunto de arquivos, de forma organizada e pesquisável. Cada commit tem um autor, uma data, uma mensagem e um identificador único. Isso significa que você pode, a qualquer momento, perguntar ao Git coisas como "quem mudou essa linha e quando?" ou "como esse arquivo estava há duas semanas?" — coisas praticamente impossíveis de responder com a técnica do _final_v2.

Dica Pense em commits como parágrafos de uma redação bem escrita: cada um deveria contar uma "ideia" completa e coerente ("adiciona formulário de login", "corrige cálculo de frete"), não ser um amontoado aleatório de mudanças sem relação entre si. Vamos falar mais sobre isso na última lição desta trilha.

Repositório local vs. repositório remoto

Um repositório (ou "repo") é simplesmente a pasta do seu projeto sendo controlada pelo Git — com todo o histórico de commits guardado dentro dela, numa subpasta escondida chamada .git. Existem dois lugares onde um repositório pode existir, e entender a diferença entre eles evita boa parte da confusão de quem está começando:

  • Repositório local: é a cópia do projeto que vive no seu próprio computador, dentro da pasta onde você está trabalhando. Todos os commits que você cria primeiro ficam só ali, guardados localmente — o Git funciona perfeitamente até sem internet.
  • Repositório remoto: é uma cópia do mesmo histórico guardada num servidor, geralmente na internet, para que outras pessoas (e você, de outro computador) possam acessá-la. O GitHub é o serviço mais popular para hospedar repositórios remotos — mas repare que GitHub não é o Git em si, é apenas um serviço que hospeda repositórios Git na nuvem e adiciona ferramentas de colaboração em cima dele (vamos ver essa diferença com calma numa lição futura).

Na prática, o fluxo comum é: você trabalha no repositório local, criando commits conforme avança, e de tempos em tempos envia ("push") esses commits para o repositório remoto, para que fiquem salvos na nuvem e disponíveis para o resto da equipe. Da mesma forma, você pode trazer ("pull") os commits que outras pessoas enviaram, para manter sua cópia local atualizada.

Atenção Git e GitHub não são a mesma coisa, mesmo que os nomes pareçam iguais. O Git é o programa que roda no seu computador e controla as versões do projeto. O GitHub é um site que guarda cópias remotas desses repositórios e adiciona recursos como pull requests, issues e revisão de código — assunto de uma lição mais à frente nesta trilha.

Por que isso importa mesmo fora da programação

Ainda que o Git seja usado quase exclusivamente por quem programa, a ideia por trás dele é universal: qualquer trabalho que evolui ao longo do tempo, feito por uma ou várias pessoas, se beneficia de ter um histórico claro de mudanças, a possibilidade de voltar atrás sem medo, e uma forma organizada de juntar o trabalho de várias pessoas sem sobrescrever nada. É exatamente essa segurança — "posso experimentar, porque sempre consigo voltar" — que faz o Git ser considerado uma ferramenta essencial, e não um luxo, no dia a dia de quem desenvolve software.

Resumo

  • Controle de versão resolve o problema de arquivos duplicados como "final_v2_definitivo.docx".
  • Um commit é uma "fotografia" do projeto num momento específico, com autor, data e mensagem.
  • O Git guarda o histórico completo de mudanças, permitindo voltar no tempo e comparar versões.
  • Repositório local vive no seu computador; repositório remoto vive num servidor, como o GitHub.
  • Git é a ferramenta; GitHub é um serviço que hospeda repositórios Git e adiciona colaboração.
