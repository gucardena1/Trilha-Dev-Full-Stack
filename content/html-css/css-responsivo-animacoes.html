2. HTML & CSS

Responsividade e animações

Fazer a página se adaptar a qualquer tela e dar vida às interações, sem exagerar.

Analogia Pense numa roupa sob medida versus uma roupa elástica. Uma página não responsiva é como uma camisa sob medida para uma pessoa específica: fica perfeita nela, mas não veste ninguém de tamanho diferente. Uma página responsiva é como uma roupa de tecido elástico bem cortado: se ajusta ao corpo de quem está usando, seja um celular pequeno ou uma tela de desktop enorme, sem parecer errada em nenhum dos dois.

Por que responsividade não é opcional

Mais da metade do tráfego da internet hoje em dia vem de celulares. Uma página desenhada só pensando em telas grandes de computador frequentemente fica quebrada, cortada ou exige zoom e rolagem lateral em um celular — uma experiência ruim o suficiente para fazer a pessoa simplesmente sair do site. Responsividade é a técnica de fazer o layout se adaptar ao tamanho da tela de quem está visitando.

A meta tag viewport

Antes de qualquer CSS responsivo, toda página precisa desta linha no <head> (você já viu ela no template usado em toda esta trilha): 

<meta name="viewport" content="width=device-width, initial-scale=1.0" />

Sem essa linha, navegadores de celular assumem que a página foi feita para uma tela de desktop e simplesmente encolhem tudo, forçando a pessoa a dar zoom para ler qualquer coisa. Essa meta tag diz "a largura da página deve ser igual à largura real do dispositivo, e comece com o zoom em 100%".

Media queries: regras que dependem do tamanho da tela

Uma media query é um bloco de CSS que só se aplica quando uma condição sobre a tela é verdadeira — a mais comum sendo a largura da janela. A sintaxe usa @media: 

/* Estilo padrão, para qualquer tela */
.cartoes {
  display: grid;
  grid-template-columns: 1fr;
}

/* A partir de 768px de largura, muda para 3 colunas */
@media (min-width: 768px) {
  .cartoes {
    grid-template-columns: 1fr 1fr 1fr;
  }
}

Nesse exemplo, em uma tela estreita (celular) os cartões ficam empilhados, um por linha. Quando a tela atinge 768px de largura ou mais (tablets e desktops), a regra dentro da media query entra em ação e muda para três colunas lado a lado.

Faixa de largura aproximadaTipo de dispositivo comum
até 480pxCelulares
481px a 768pxTablets em pé, celulares grandes deitados
769px a 1024pxTablets deitados, notebooks pequenos
acima de 1024pxDesktops e notebooks maiores
Dica Esses números não são regras fixas gravadas em pedra — são convenções comuns do mercado. O ideal é sempre testar a sua própria página redimensionando a janela do navegador (ou usando o modo de dispositivo do DevTools) e criar um "breakpoint" (ponto de quebra) exatamente onde o seu layout específico começa a parecer ruim, não em um número mágico decorado.

Mobile-first: comece pequeno, depois cresça

Mobile-first é a estratégia de escrever o CSS padrão (fora de qualquer media query) pensando primeiro no celular — a tela menor e mais restrita — e depois usar min-width para adicionar melhorias progressivas conforme a tela cresce. É o oposto de escrever primeiro para desktop e depois "consertar" para celular com max-width. 

/* Mobile-first: este é o padrão, já pensado para celular */
.menu {
  display: flex;
  flex-direction: column;
}

/* Melhora progressiva para telas maiores */
@media (min-width: 768px) {
  .menu {
    flex-direction: row;
  }
}

A vantagem prática: o layout mais simples (empilhado, uma coluna) já funciona em qualquer tela por padrão, mesmo se uma media query específica não disparar por algum motivo. Você vai "adicionando" complexidade conforme o espaço disponível cresce, em vez de "removendo" complexidade quando o espaço encolhe.

Erro comum Testar responsividade apenas redimensionando a janela do navegador no computador. A simulação ajuda, mas não substitui testar em um celular de verdade (ou pelo menos no modo de emulação de dispositivo do DevTools) — coisas como tamanho de toque dos botões e comportamento do teclado virtual só aparecem de verdade lá.

Transitions: suavizando mudanças de estado

Uma transition (transição) diz ao navegador: "quando uma propriedade CSS mudar de valor, não troque de uma vez — anime a mudança suavemente ao longo de um tempo". É o jeito mais simples de dar uma sensação de "vida" a botões e links, por exemplo, quando o mouse passa por cima (:hover). 

.botao {
  background-color: #2f6fed;
  color: white;
  padding: 10px 20px;
  border-radius: 6px;
  transition: background-color 0.2s ease, transform 0.2s ease;
}

.botao:hover {
  background-color: #1c4fc0;
  transform: translateY(-2px);
}

Sem o transition, a cor de fundo mudaria instantaneamente ao passar o mouse — funcional, mas seco. Com ele, a mudança de cor e o pequeno deslocamento para cima (translateY(-2px)) acontecem suavemente em 0.2 segundos, dando uma sensação de resposta física ao clique.

Parte da propriedade transitionSignifica
background-colorQual propriedade CSS será animada.
0.2sDuração da animação.
easeCurva de aceleração: começa rápido, desacelera no fim (a mais natural para a maioria dos casos).

Animations: sequências mais elaboradas

Quando você precisa de algo mais complexo do que "do estado A para o estado B" — como um elemento pulsando continuamente, ou uma sequência com vários passos — usa-se @keyframes junto com a propriedade animation. 

@keyframes pulsar {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.1); }
  100% { transform: scale(1); }
}

.notificacao {
  animation: pulsar 1.5s ease-in-out infinite;
}

O @keyframes define os "quadros-chave" da animação: em 0% do tempo (o início), o elemento está no tamanho normal; em 50% (na metade), ele cresce 10%; em 100% (no fim), volta ao normal. A propriedade animation na classe .notificacao aplica essa sequência com duração de 1.5 segundos, repetindo infinite-amente — útil, por exemplo, para chamar atenção para um ícone de notificação nova.

SituaçãoMelhor ferramenta
Mudança simples de A para B (cor no hover, aparecer/sumir)transition
Sequência com múltiplos passos ou que se repete sozinhaanimation + @keyframes
Dica Use animações com moderação. Elas devem dar clareza (mostrar que um botão foi clicado, que algo novo chegou) — não distrair ou deixar a pessoa esperando. Evite animar propriedades pesadas para o navegador processar, como width ou height; prefira animar transform e opacity, que são muito mais leves de calcular e rodam de forma mais suave.

Exemplo completo: cartão responsivo com hover animado

<style>
  .grade {
    display: grid;
    grid-template-columns: 1fr;
    gap: 16px;
    padding: 16px;
  }

  @media (min-width: 768px) {
    .grade {
      grid-template-columns: repeat(3, 1fr);
    }
  }

  .cartao {
    border: 1px solid #ddd;
    border-radius: 8px;
    padding: 16px;
    transition: transform 0.2s ease, box-shadow 0.2s ease;
  }

  .cartao:hover {
    transform: translateY(-4px);
    box-shadow: 0 8px 16px rgba(0, 0, 0, 0.15);
  }
</style>

<div class="grade">
  <div class="cartao">Produto 1</div>
  <div class="cartao">Produto 2</div>
  <div class="cartao">Produto 3</div>
</div>

No celular, os cartões ficam empilhados em uma coluna só (o padrão mobile-first). A partir de 768px de largura, viram três colunas. E ao passar o mouse sobre qualquer cartão, ele sobe levemente e ganha uma sombra, de forma suave, graças ao transition. É um exemplo pequeno, mas reúne tudo que essa lição trouxe: responsividade e uma animação sutil que melhora a experiência sem atrapalhar.

Resumo

  • A meta tag viewport é obrigatória para qualquer responsividade funcionar em celulares.
  • Media queries (@media (min-width: ...)) aplicam regras CSS só a partir de certas larguras de tela.
  • Mobile-first: escreva o CSS padrão para telas pequenas, depois use min-width para adicionar melhorias em telas maiores.
  • transition anima suavemente a mudança entre dois estados (ex: hover).
  • @keyframes + animation criam sequências mais elaboradas e repetíveis.
  • Prefira animar transform e opacity, que são mais leves para o navegador processar.
