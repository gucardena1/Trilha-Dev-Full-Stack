2. HTML & CSS

Semântica, formulários e acessibilidade

Tags que contam a história certa da página e campos que coletam informação de quem visita.

Analogia Imagine a planta de uma casa desenhada só com retângulos sem nenhuma legenda: você não sabe se aquele retângulo é a cozinha, o quarto ou a garagem. Funciona, mas ninguém entende nada só de olhar. Agora imagine a mesma planta com cada cômodo etiquetado: "cozinha", "sala", "quarto 1". É a diferença entre uma página feita só de <div> genéricas e uma página com HTML semântico: tags que já dizem, pelo próprio nome, o que aquele pedaço da página representa.

Por que a semântica importa

Você poderia construir qualquer página inteira usando apenas a tag <div>, que é uma caixa genérica sem significado algum. Ela funciona, mas é como etiquetar todas as caixas de uma mudança como "coisas". Ninguém — nem você no futuro, nem o Google, nem um leitor de tela usado por uma pessoa cega — consegue entender rapidamente o que está ali dentro.

Tags semânticas resolvem isso descrevendo o papel do conteúdo. Os três benefícios práticos são:

  • Leitura por máquinas: buscadores como o Google entendem melhor do que trata a página, o que ajuda no posicionamento em pesquisas.
  • Acessibilidade: leitores de tela (softwares que leem a página em voz alta para pessoas com deficiência visual) usam essas tags para anunciar "isto é o menu principal", "isto é o rodapé", permitindo navegação rápida por seções.
  • Organização para quem programa: fica muito mais fácil entender e dar manutenção num código que já se explica pelos nomes das tags.

As principais tags semânticas de estrutura

Pense numa página de notícias: ela tem um cabeçalho, um menu, o conteúdo principal, uma barra lateral e um rodapé. HTML tem uma tag para cada um desses papéis:

TagRepresenta
<header>Cabeçalho da página ou de uma seção: logo, título, menu de navegação.
<nav>Bloco de links de navegação (menu principal, menu de rodapé).
<main>O conteúdo principal e único daquela página. Deve aparecer só uma vez.
<section>Uma seção temática dentro da página, geralmente com seu próprio título.
<article>Um conteúdo independente que faria sentido sozinho: um post de blog, uma notícia, um comentário.
<aside>Conteúdo relacionado mas secundário: uma barra lateral, um box de "veja também".
<footer>Rodapé: direitos autorais, links de contato, redes sociais.
<body>
  <header>
    <h1>Blog da Cozinha</h1>
    <nav>
      <a href="/">Início</a>
      <a href="/receitas">Receitas</a>
    </nav>
  </header>

  <main>
    <article>
      <h2>Bolo de cenoura</h2>
      <p>Uma receita clássica e fácil.</p>
    </article>

    <aside>
      <h3>Receitas parecidas</h3>
      <p>Bolo de chocolate, bolo de fubá.</p>
    </aside>
  </main>

  <footer>
    <p>&copy; 2026 Blog da Cozinha</p>
  </footer>
</body>
Dica Regra prática: use <div> apenas quando nenhuma tag semântica descreve o que você está agrupando (por exemplo, um "wrapper" só para aplicar um estilo). Se existe uma tag que já diz o que aquilo é — cabeçalho, artigo, navegação — prefira ela.

Formulários: coletando dados de quem visita

Um formulário é como uma ficha de cadastro em papel: tem campos para preencher e, no fim, um botão de "enviar". Em HTML, tudo começa com a tag <form>, que envolve todos os campos. 

<form>
  <label for="nome">Nome:</label>
  <input type="text" id="nome" name="nome" />

  <label for="email">E-mail:</label>
  <input type="email" id="email" name="email" />

  <button type="submit">Enviar</button>
</form>

O elemento mais usado dentro de um formulário é o <input>, cujo comportamento muda de acordo com o atributo type:

Valor de typeO que cria
textCampo de texto simples, uma linha.
emailCampo de texto que valida um formato de e-mail.
passwordCampo de texto que esconde os caracteres digitados.
numberCampo que aceita apenas números.
checkboxCaixa de marcar (sim/não, várias opções podem estar marcadas ao mesmo tempo).
radioBotão de opção única entre um grupo (só um pode ficar marcado).
dateSeletor de data.

Outros elementos comuns de formulário são o <textarea>, para textos longos de várias linhas, e o <select>, para uma lista suspensa de opções: 

<label for="mensagem">Mensagem:</label>
<textarea id="mensagem" name="mensagem" rows="4"></textarea>

<label for="estado">Estado:</label>
<select id="estado" name="estado">
  <option value="sp">São Paulo</option>
  <option value="rj">Rio de Janeiro</option>
</select>

label + for: a dupla que ninguém pode esquecer

Repare que cada <input> no exemplo tem um <label> associado, ligado pelo atributo for, que precisa ser idêntico ao id do campo. Isso não é só estético: clicar no texto do label também foca o campo (tente clicar na palavra "Nome:" de um formulário real — o cursor vai para a caixa de texto). E para quem usa leitor de tela, é o label que é lido em voz alta quando o campo recebe foco, dizendo o que se espera ali.

Erro comum Criar um <input> sem <label>, contando só com um texto solto do lado como "Nome:". Visualmente parece igual, mas para quem usa leitor de tela ou tecnologia assistiva, esse campo não tem nome nenhum — vira "campo de texto em branco". Sempre associe um <label> de verdade, usando for e id combinando.

Atributos de acessibilidade essenciais

Além de escolher as tags certas, alguns atributos ajudam diretamente pessoas que usam tecnologia assistiva:

  • alt em imagens — já vimos na lição anterior. Sem ele, uma imagem é só um vazio de silêncio para quem não pode vê-la.
  • aria-label — dá um nome acessível a um elemento quando não há texto visível suficiente, como um botão que só tem um ícone: <button aria-label="Fechar">X</button>.
  • aria-hidden="true" — esconde um elemento decorativo (um ícone puramente visual, por exemplo) de leitores de tela, para não gerar ruído.
  • required — marca um campo de formulário como obrigatório; o navegador já bloqueia o envio e avisa a pessoa se ele estiver vazio.
<button aria-label="Fechar janela">✕</button>

<input type="email" name="email" required />
Dica Uma forma simples de testar a acessibilidade básica da sua página: navegue por ela usando só a tecla Tab do teclado, sem usar o mouse. Se você consegue chegar em todos os links, botões e campos de formulário, em uma ordem que faz sentido, você já está no caminho certo.

Exemplo completo: página semântica com formulário

<body>
  <header>
    <h1>Fale conosco</h1>
  </header>

  <main>
    <section>
      <h2>Envie sua mensagem</h2>
      <form>
        <label for="nome">Nome:</label>
        <input type="text" id="nome" name="nome" required />

        <label for="assunto">Assunto:</label>
        <select id="assunto" name="assunto">
          <option value="duvida">Dúvida</option>
          <option value="elogio">Elogio</option>
        </select>

        <label for="mensagem">Mensagem:</label>
        <textarea id="mensagem" name="mensagem" rows="5"></textarea>

        <button type="submit">Enviar</button>
      </form>
    </section>
  </main>

  <footer>
    <p>&copy; 2026 Minha Empresa</p>
  </footer>
</body>

Resumo

  • Tags semânticas (header, main, section, article, aside, footer) descrevem o papel do conteúdo, não só agrupam caixas.
  • Use <div> só quando nenhuma tag semântica se encaixa.
  • Formulários começam em <form> e usam <input>, <textarea> e <select> para coletar dados.
  • Todo campo precisa de um <label> associado via for/id.
  • alt, aria-label e required tornam a página utilizável por mais pessoas.
  • Teste sua página navegando só com o teclado (Tab) para checar acessibilidade básica.
