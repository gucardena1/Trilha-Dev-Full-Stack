7. Vue.js

Vue Router e Pinia

Como navegar entre "páginas" dentro de uma SPA e como compartilhar dados entre componentes distantes.

Até agora, todo componente que você viu vivia isolado ou dentro de uma cadeia direta de pai e filho, trocando dados por props e eventos. Isso funciona bem para telas pequenas, mas duas necessidades novas aparecem conforme a aplicação cresce: primeiro, o usuário precisa navegar entre diferentes "telas" (uma página de produtos, uma página de perfil, uma página de login) sem recarregar o site inteiro; segundo, alguns dados precisam ser acessados por componentes que não têm relação direta de pai/filho entre si (o carrinho de compras, por exemplo, é usado tanto no cabeçalho quanto na página de checkout). Essas duas necessidades são resolvidas por duas bibliotecas oficiais do ecossistema Vue: o Vue Router e o Pinia.

O que é uma SPA e por que roteamento importa

Um site tradicional funciona assim: cada URL que você acessa faz o navegador pedir uma página HTML nova inteira ao servidor, e a tela toda "pisca" e recarrega. Uma SPA (Single Page Application, "aplicação de página única") funciona diferente: o navegador carrega um único arquivo HTML no começo, e o JavaScript (o Vue, nesse caso) troca o conteúdo da tela dinamicamente conforme o usuário navega, sem nunca recarregar a página inteira. Isso deixa a navegação muito mais rápida e fluida, parecida com um aplicativo de celular. O problema é que, sem nenhuma ferramenta extra, a URL do navegador não mudaria conforme o usuário navega dentro da SPA — e sem URLs diferentes para cada "tela", você perde coisas essenciais como o botão de voltar do navegador, compartilhar um link direto para uma página específica, ou recarregar a página e continuar no mesmo lugar. O Vue Router resolve exatamente isso: ele observa a URL, decide qual componente mostrar com base nela, e atualiza a URL quando o usuário navega — tudo sem nenhum recarregamento de página.

Configurando rotas básicas

Um arquivo de configuração de rotas típico associa caminhos de URL a componentes: 

// router.js
import { createRouter, createWebHistory } from 'vue-router'
import Home from './paginas/Home.vue'
import Produtos from './paginas/Produtos.vue'
import ProdutoDetalhe from './paginas/ProdutoDetalhe.vue'

const routes = [
  { path: '/', component: Home },
  { path: '/produtos', component: Produtos },
  { path: '/produtos/:id', component: ProdutoDetalhe }
]

export const router = createRouter({
  history: createWebHistory(),
  routes
})

Repare na rota /produtos/:id — os dois-pontos indicam um parâmetro dinâmico: qualquer valor nessa posição da URL (por exemplo, /produtos/42) é capturado e fica disponível dentro do componente ProdutoDetalhe através de useRoute(): 

<script setup>
import { useRoute } from 'vue-router'

const route = useRoute()
// se a URL for /produtos/42, route.params.id vale "42"
console.log(route.params.id)
</script>

No componente principal da aplicação, você precisa de dois elementos fornecidos pelo Vue Router: <router-link> para criar links de navegação sem recarregar a página, e <router-view>, que é o "espaço reservado" onde o componente da rota atual é exibido: 

<template>
  <nav>
    <router-link to="/">Início</router-link>
    <router-link to="/produtos">Produtos</router-link>
  </nav>

  <router-view />
</template>
Dica Use sempre <router-link> em vez de uma tag <a href="..."> comum para navegação interna da SPA. Um <a> normal faria o navegador recarregar a página inteira, perdendo justamente a vantagem de velocidade que uma SPA oferece.

Quando você precisa de gerenciamento de estado global

Com props e eventos, dados fluem naturalmente entre pai e filho. Mas o que acontece quando dois componentes que não têm relação direta precisam compartilhar informação — por exemplo, o ícone do carrinho no cabeçalho e a página de checkout, que moram em partes completamente diferentes da árvore de componentes? Você poderia tentar "subir" o dado até um ancestral comum e descer via props por vários níveis, mas isso cria um problema conhecido como prop drilling: passar uma prop por três, quatro, cinco componentes intermediários que nem usam aquele dado, só para repassá-lo adiante. Quando isso acontece com frequência na sua aplicação, é sinal de que você precisa de um gerenciamento de estado global: um lugar único, fora da árvore de componentes, onde dados compartilhados vivem e de onde qualquer componente pode ler e atualizar diretamente, sem depender de props e eventos passando por intermediários.

Pinia: a store oficial do Vue

O Pinia é a biblioteca oficial de gerenciamento de estado do Vue (sucessora do antigo Vuex). Uma store no Pinia é, na prática, um composable especial que pode ser usado por qualquer componente da aplicação, sem precisar de props: 

// stores/carrinho.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useCarrinhoStore = defineStore('carrinho', () => {
  const itens = ref([])

  const total = computed(() =>
    itens.value.reduce((soma, item) => soma + item.preco, 0)
  )

  function adicionar(produto) {
    itens.value.push(produto)
  }

  function remover(indice) {
    itens.value.splice(indice, 1)
  }

  return { itens, total, adicionar, remover }
})

Repare que essa store usa exatamente as mesmas ferramentas que você já conhece — ref, computed — só que declaradas fora de qualquer componente, num arquivo próprio. Isso é chamado de "Setup Store" (o mesmo estilo do <script setup>, aplicado a uma store). Agora, qualquer componente da aplicação pode usar essa store diretamente: 

<!-- Cabecalho.vue -->
<script setup>
import { useCarrinhoStore } from '../stores/carrinho.js'

const carrinho = useCarrinhoStore()
</script>

<template>
  <span>🛒 {{ carrinho.itens.length }} itens</span>
</template>
<!-- PaginaProduto.vue -->
<script setup>
import { useCarrinhoStore } from '../stores/carrinho.js'

const carrinho = useCarrinhoStore()

function comprar(produto) {
  carrinho.adicionar(produto)
}
</script>

Os dois componentes acima podem estar em qualquer lugar da aplicação, sem nenhuma relação de pai/filho entre eles, e mesmo assim compartilham o mesmo estado do carrinho em tempo real: quando PaginaProduto chama carrinho.adicionar(...), o Cabecalho atualiza sozinho, porque ambos estão lendo da mesma store reativa.

Atenção Nem todo dado precisa virar estado global. Se um dado só é usado dentro de um componente e talvez em um filho direto, props e ref local já resolvem — criar uma store para isso é complexidade desnecessária. Reserve o Pinia para dados que realmente precisam ser acessados por partes distantes e não relacionadas da aplicação: usuário logado, carrinho de compras, tema (claro/escuro), preferências globais.

Resumo

  • Uma SPA troca o conteúdo da tela via JavaScript sem recarregar a página; o Vue Router mantém a URL sincronizada com o que está sendo mostrado.
  • Rotas associam caminhos de URL a componentes; :parametro na rota captura valores dinâmicos, acessíveis via useRoute().params.
  • <router-link> navega sem recarregar a página; <router-view> é onde o componente da rota atual aparece.
  • Gerenciamento de estado global evita "prop drilling" quando componentes sem relação direta precisam compartilhar dados.
  • O Pinia cria stores reativas (com ref/computed) acessíveis por qualquer componente, sem precisar passar props por intermediários.
