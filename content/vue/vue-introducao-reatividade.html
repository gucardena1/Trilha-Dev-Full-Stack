7. Vue.js

Introdução ao Vue e reatividade

O que é um framework frontend, por que ele existe, e o conceito que sustenta tudo no Vue: a reatividade.

Você já sabe JavaScript puro: manipular o DOM com document.querySelector, escutar eventos com addEventListener, atualizar a tela "na mão" toda vez que algo muda. Funciona, mas em telas grandes vira um pesadelo de manutenção: você precisa lembrar, para cada pedacinho de dado, exatamente quais partes da tela dependem dele e atualizar cada uma manualmente. Um framework frontend como o Vue existe para resolver esse problema específico: você diz o que a tela deve mostrar com base nos dados que você tem, e o framework cuida de manter a tela sincronizada sempre que os dados mudam.

Por que usar um framework em vez de JavaScript puro?

Pense numa página de carrinho de compras. Quando o usuário adiciona um item, várias coisas na tela precisam mudar ao mesmo tempo: a lista de produtos, o contador de itens no ícone do carrinho, o valor total, talvez uma mensagem de "produto adicionado". Em JavaScript puro, você teria que escrever código para atualizar cada um desses pedaços, um por um, toda vez que qualquer coisa mudasse. É fácil esquecer de atualizar algum deles e deixar a tela com informação desatualizada (um bug clássico chamado "dessincronização de estado"). O Vue resolve isso invertendo a lógica: você declara uma vez "o contador do carrinho mostra carrinho.length" e, a partir daí, sempre que carrinho mudar, o Vue atualiza esse pedaço da tela sozinho — sem você escrever mais nenhuma linha para isso.

Analogia Pense numa planilha do Excel. Você escreve na célula C1 a fórmula =A1+B1. A partir daquele momento, você nunca mais precisa calcular essa soma na mão: sempre que mudar o valor de A1 ou B1, a célula C1 se atualiza sozinha, na hora. Você não "manda" o Excel recalcular — ele simplesmente sabe que C1 depende de A1 e B1, e reage automaticamente quando um dos dois muda. A reatividade no Vue é exatamente esse comportamento, só que aplicado à tela do seu site em vez de células de planilha: você liga um pedaço de HTML a um dado, e sempre que o dado muda, aquele pedaço de tela "recalcula" e se atualiza sozinho.

O que é reatividade, tecnicamente

Reatividade é a capacidade de um sistema perceber quando um valor mudou e reagir automaticamente a essa mudança, atualizando tudo o que depende dele. No Vue, você marca quais variáveis são "reativas" (isto é, o Vue deve vigiá-las) e escreve o HTML dizendo quais partes usam essas variáveis. O Vue faz o resto: ele observa as variáveis marcadas e, quando alguma muda, re-renderiza apenas os pedaços de tela que dependem dela — não a página inteira, só o necessário.

Criando seu primeiro componente com ref

A forma mais simples de criar um valor reativo no Vue 3 é a função ref(). Ela recebe um valor inicial e devolve um "objeto caixinha" reativo: para ler ou mudar o valor de dentro dessa caixinha, em código JavaScript, você usa .value. No template (o HTML), você usa o nome direto, sem .value — o Vue cuida dessa "desembrulhada" automaticamente. 

<script setup>
import { ref } from 'vue'

// contador é um valor reativo, começando em 0
const contador = ref(0)

function incrementar() {
  // no JavaScript, sempre acessamos/alteramos via .value
  contador.value++
}
</script>

<template>
  <div>
    <!-- no template, usamos "contador" direto, sem .value -->
    <p>Você clicou {{ contador }} vezes</p>
    <button @click="incrementar">Clicar</button>
  </div>
</template>

Repare que nada nesse código diz explicitamente "atualize o parágrafo quando contador mudar". Isso é exatamente o ponto: o Vue detecta que o texto {{ contador }} depende dessa variável reativa, e sempre que contador.value mudar (por exemplo, dentro de incrementar), o parágrafo é atualizado sozinho na tela.

<script setup>: a sintaxe moderna

Toda a trilha vai usar <script setup>, que é a forma recomendada de escrever componentes Vue 3 hoje em dia. Um arquivo de componente Vue (extensão .vue) tem três partes: <script setup> (a lógica em JavaScript), <template> (o HTML) e, opcionalmente, <style> (o CSS daquele componente). Tudo o que você declara dentro de <script setup> — variáveis, funções — fica automaticamente disponível para uso no <template>, sem precisar de nenhum passo extra de "exportar" essas coisas.

data na Options API (o que você vai ver por aí)

Antes do <script setup> se tornar popular, o Vue já existia com outra sintaxe, chamada Options API, que organiza o componente em um objeto com propriedades como data, methods, computed. Você ainda vai encontrar muito código assim em projetos antigos e tutoriais, então vale reconhecer: 

export default {
  data() {
    return {
      contador: 0
    }
  },
  methods: {
    incrementar() {
      this.contador++
    }
  }
}

Na Options API, tudo que está dentro de data() vira reativo automaticamente — não existe .value aqui, você acessa direto via this.contador. O resultado final (a tela reagindo às mudanças) é o mesmo dos dois jeitos; a diferença é só de organização do código. Vamos comparar as duas abordagens com mais profundidade na lição sobre Composition API, mas por enquanto, foque em entender e praticar ref.

Dica Uma forma simples de saber se você precisa de ref(): se o valor pode mudar ao longo do tempo e a tela precisa refletir essa mudança, use ref. Se o valor nunca muda (uma constante, uma configuração fixa), uma variável comum do JavaScript já basta — não precisa "envolver" tudo em ref por hábito.
Atenção Um erro comum de quem está começando é esquecer o .value dentro do <script setup>. Escrever contador++ em vez de contador.value++ não gera erro visível na hora, mas também não atualiza nada — porque você estaria mexendo em uma variável comum, não no valor de dentro da caixinha reativa. Lembre-se: .value no JavaScript, nome direto no template.

Instalando e rodando um projeto Vue

Para experimentar os exemplos desta trilha, o caminho mais simples é criar um projeto com o Vite (a ferramenta de build oficial recomendada pelo time do Vue): 

npm create vue@latest
cd meu-projeto
npm install
npm run dev

Isso abre um servidor local (geralmente em http://localhost:5173) que recarrega a página automaticamente a cada alteração salva no código — muito mais rápido para aprender do que ficar recarregando a página na mão.

Resumo

  • Um framework frontend existe para manter a tela sincronizada com os dados automaticamente, sem você atualizar o DOM manualmente pedaço por pedaço.
  • Reatividade é o mecanismo que detecta mudanças em um valor e atualiza sozinho tudo o que depende dele — como fórmulas de uma planilha de Excel.
  • ref() transforma um valor comum em um valor reativo; no JavaScript acessa-se com .value, no template usa-se o nome direto.
  • <script setup> é a sintaxe moderna do Vue 3 usada nesta trilha; a Options API (com data/methods) é a forma mais antiga, ainda comum em projetos legados.
  • O Vite é a ferramenta padrão para criar e rodar projetos Vue localmente com recarregamento automático.
