7. Vue.js

Componentes, props e eventos

Como quebrar uma tela em pedaços reutilizáveis e como esses pedaços conversam entre si.

Na lição anterior você viu um componente sozinho, com um botão e um contador. Mas nenhum site de verdade é feito de um único bloco de código gigante — ele é montado a partir de pedaços menores, cada um responsável por uma parte específica da tela. No Vue, esses pedaços se chamam componentes, e aprender a dividir uma interface em componentes bem definidos é uma das habilidades mais importantes que você vai desenvolver.

Analogia Pense em peças de Lego. Cada peça é pequena, simples e serve para um propósito claro — uma peça de 2x4, uma roda, uma dobradiça. Sozinha, uma peça não parece grande coisa, mas combinando várias peças diferentes você monta um carro, uma casa, um castelo. O segredo é que as peças são reutilizáveis: a mesma peça de roda serve tanto no carrinho quanto no caminhão do seu conjunto de Lego. Um componente Vue é essa peça: um pedaço de tela (com seu próprio HTML, lógica e às vezes estilo) que você projeta uma vez e reutiliza em vários lugares da aplicação — um CartaoProduto, um Botao, um Modal de confirmação.

Criando e usando um componente

Um componente Vue geralmente é um arquivo .vue próprio. Imagine um arquivo CartaoProduto.vue: 

<!-- CartaoProduto.vue -->
<script setup>
const props = defineProps({
  nome: String,
  preco: Number
})
</script>

<template>
  <div class="cartao">
    <h3>{{ nome }}</h3>
    <p>R$ {{ preco.toFixed(2) }}</p>
  </div>
</template>

E, em outro componente (por exemplo, a página que lista produtos), você usa essa peça várias vezes, mudando apenas os dados: 

<script setup>
import CartaoProduto from './CartaoProduto.vue'
</script>

<template>
  <div>
    <CartaoProduto nome="Teclado mecânico" :preco="350" />
    <CartaoProduto nome="Mouse sem fio" :preco="120" />
  </div>
</template>

Repare que a mesma "peça de Lego" CartaoProduto foi usada duas vezes, cada vez com dados diferentes. Isso é reuso de componente na prática.

Props: dados que descem do pai para o filho

No exemplo acima, nome e preco são props (abreviação de "properties"). Props são a forma de um componente pai passar dados para um componente filho — sempre numa via de mão única, de cima para baixo. O filho declara quais props aceita com defineProps, e o pai as preenche como se fossem atributos HTML. Note a diferença de sintaxe: nome="..." passa um texto fixo, enquanto :preco="350" (com dois-pontos na frente) passa uma expressão JavaScript — nesse caso, o número 350, não o texto "350".

Atenção Props são de leitura para o componente filho — nunca altere uma prop diretamente dentro do componente que a recebeu, como em props.preco = 100. O Vue vai avisar com um erro no console porque isso quebra a ideia de "fluxo de dados em uma via só": se o filho pudesse mudar a prop livremente, o pai perderia o controle sobre seus próprios dados. Se você precisa de uma versão modificável do valor, copie a prop para uma variável reativa própria dentro do filho, ou melhor ainda, avise o pai (via evento, como você vai ver a seguir) para que seja ele a mudar o dado original.

Eventos: o filho avisando o pai

Se props é a via "de cima para baixo", eventos são a via "de baixo para cima": um componente filho não pode mudar os dados do pai diretamente, mas pode emitir um evento avisando "algo aconteceu aqui", e é o pai quem decide o que fazer com essa informação. Isso se faz com defineEmits: 

<!-- BotaoCurtir.vue -->
<script setup>
const emit = defineEmits(['curtiu'])

function aoClicar() {
  // avisa quem estiver usando este componente que o clique aconteceu
  emit('curtiu')
}
</script>

<template>
  <button @click="aoClicar">❤ Curtir</button>
</template>
<!-- componente pai -->
<script setup>
import { ref } from 'vue'
import BotaoCurtir from './BotaoCurtir.vue'

const curtidas = ref(0)

function incrementarCurtidas() {
  curtidas.value++
}
</script>

<template>
  <p>{{ curtidas }} curtidas</p>
  <BotaoCurtir @curtiu="incrementarCurtidas" />
</template>

O componente BotaoCurtir não sabe nem se importa com o que o pai vai fazer quando alguém clicar — ele só avisa "curtiu" e segue a vida. Quem decide o que acontece (incrementar um contador, salvar no banco, mostrar uma animação) é sempre o pai, através do @curtiu="...". Essa separação de responsabilidades é o que torna componentes reutilizáveis em contextos muito diferentes: o mesmo BotaoCurtir poderia ser usado numa tela de fotos e numa tela de comentários, cada uma reagindo do seu próprio jeito ao mesmo evento.

v-model: props e eventos trabalhando juntos

Um padrão tão comum — passar um valor via prop e emitir um evento para avisar quando ele muda — que o Vue tem um atalho para isso: o v-model. Você já deve tê-lo visto em inputs comuns: 

<script setup>
import { ref } from 'vue'
const nomeUsuario = ref('')
</script>

<template>
  <input v-model="nomeUsuario" placeholder="Seu nome" />
  <p>Olá, {{ nomeUsuario }}!</p>
</template>

Por trás dos panos, v-model num input nada mais é do que açúcar sintático para "passar o valor atual como prop value e escutar o evento input para atualizar a variável". Você pode criar esse mesmo comportamento nos seus próprios componentes, aceitando uma prop modelValue e emitindo update:modelValue: 

<!-- CampoTexto.vue -->
<script setup>
defineProps(['modelValue'])
defineEmits(['update:modelValue'])
</script>

<template>
  <input
    :value="modelValue"
    @input="$emit('update:modelValue', $event.target.value)"
  />
</template>

Feito isso, quem usar <CampoTexto v-model="nomeUsuario" /> ganha o mesmo comportamento de sincronização automática que os inputs nativos têm — o componente filho recebe o valor via prop e avisa o pai a cada mudança via evento, tudo escondido atrás da sintaxe simples do v-model.

Dica Uma boa regra para saber quando quebrar a tela em um novo componente: se um pedaço de HTML se repete em vários lugares, ou se um pedaço tem uma responsabilidade clara e isolada (um cartão, um modal, um formulário), ele provavelmente merece virar seu próprio componente. Componentes pequenos e bem definidos são muito mais fáceis de testar, reusar e entender do que um único componente gigante fazendo tudo.

Resumo

  • Componentes são pedaços de tela reutilizáveis, como peças de Lego — cada um com responsabilidade própria.
  • Props levam dados do componente pai para o componente filho, sempre em uma única direção.
  • Nunca altere uma prop diretamente dentro do filho; se precisar mudá-la, avise o pai via evento.
  • Eventos (defineEmits / emit) são a forma do filho avisar o pai sobre algo que aconteceu, sem tomar decisões por ele.
  • v-model é um atalho que combina uma prop e um evento para manter um valor sincronizado entre pai e filho.
