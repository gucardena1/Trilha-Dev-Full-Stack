7. Vue.js

Composition API

Como organizar a lógica de um componente por assunto, em vez de por tipo — e como reaproveitá-la entre componentes.

Você já vem usando a Composition API desde a primeira lição, sem talvez perceber o nome formal: toda vez que você escreveu <script setup> e usou ref(), estava usando esse estilo. Nesta lição vamos entender por que ela existe, completar as ferramentas que faltam (reactive, computed, watch) e ver como extrair lógica reutilizável em funções próprias, chamadas composables.

Options API vs. Composition API

Na Options API (o estilo mais antigo do Vue), um componente organiza seu código por tipo: todo o estado dentro de data(), todas as funções dentro de methods, todos os valores derivados dentro de computed. Isso funciona bem para componentes pequenos, mas em componentes grandes com várias funcionalidades diferentes, o código de uma única funcionalidade fica espalhado entre essas várias seções — para entender "como funciona a busca", você precisa pular entre o data, o methods e o computed, catando pedacinhos aqui e ali.

A Composition API resolve isso organizando o código por assunto (ou "feature"): tudo relacionado à busca fica junto, tudo relacionado à paginação fica junto, em blocos de código próximos dentro do <script setup>. Compare as duas versões de um mesmo componente simples de busca: 

<!-- Options API -->
<script>
export default {
  data() {
    return {
      termoBusca: '',
      produtos: ['Mouse', 'Teclado', 'Monitor']
    }
  },
  computed: {
    produtosFiltrados() {
      return this.produtos.filter(p =>
        p.toLowerCase().includes(this.termoBusca.toLowerCase())
      )
    }
  }
}
</script>
<!-- Composition API -->
<script setup>
import { ref, computed } from 'vue'

const termoBusca = ref('')
const produtos = ref(['Mouse', 'Teclado', 'Monitor'])

const produtosFiltrados = computed(() =>
  produtos.value.filter(p =>
    p.toLowerCase().includes(termoBusca.value.toLowerCase())
  )
)
</script>

Para um componente desse tamanho, a diferença parece pequena. Mas imagine um componente com busca, paginação e ordenação ao mesmo tempo: na Options API, cada uma dessas três funcionalidades teria pedaços espalhados em data, computed e methods; na Composition API, cada uma fica isolada em seu próprio bloco de código, de cima a baixo, e você pode até extrair cada bloco para uma função separada (é isso que veremos com composables).

ref vs. reactive

Além de ref(), o Vue oferece reactive() para tornar objetos inteiros reativos, sem precisar de .value: 

<script setup>
import { reactive } from 'vue'

const usuario = reactive({
  nome: 'Ana',
  idade: 28
})

function fazerAniversario() {
  usuario.idade++ // sem .value, porque é reactive
}
</script>

<template>
  <p>{{ usuario.nome }} tem {{ usuario.idade }} anos</p>
  <button @click="fazerAniversario">Fazer aniversário</button>
</template>

Na prática, a recomendação da própria documentação do Vue é: use ref() como padrão para tudo (números, textos, booleanos, arrays e até objetos), e reserve reactive() apenas para casos específicos onde você já sabe que quer um objeto reativo e não vai precisar reatribuí-lo por inteiro. Isso porque reactive tem uma armadilha importante:

Atenção Se você desestruturar um objeto reactive(), perde a reatividade das propriedades extraídas. Por exemplo: 
const usuario = reactive({ nome: 'Ana', idade: 28 })
const { idade } = usuario // "idade" aqui vira um número comum, congelado

idade++ // não atualiza nada na tela, porque "idade" perdeu a ligação com o objeto original
Isso acontece porque a reatividade do reactive() vive no objeto como um todo, não nos valores individuais soltos. Já com ref(), a reatividade vive na própria caixinha (.value), então ela pode ser passada adiante, guardada em outra variável, retornada de uma função — e continua reativa, porque você está sempre lidando com a mesma caixinha, só que sob outro nome. Se realmente precisar desestruturar um objeto reativo com segurança, existe uma função chamada toRefs() que converte cada propriedade em um ref individual antes da desestruturação.

computed: valores derivados que se atualizam sozinhos

Você já viu computed no exemplo de busca acima. A ideia central é: sempre que você tem um valor que é calculado a partir de outros valores reativos, use computed em vez de recalcular manualmente. A vantagem é que o Vue guarda o resultado em cache e só recalcula quando uma das dependências realmente muda — diferente de uma função comum, que recalcularia toda vez que fosse chamada, mesmo sem necessidade. 

const precoComDesconto = computed(() => preco.value * 0.9)

watch: reagindo a mudanças com efeitos colaterais

computed serve para derivar um novo valor. Mas às vezes você precisa apenas reagir a uma mudança sem produzir um novo valor reativo — por exemplo, fazer uma chamada à API toda vez que o termo de busca mudar, ou salvar algo no localStorage. Para isso existe watch: 

<script setup>
import { ref, watch } from 'vue'

const termoBusca = ref('')

watch(termoBusca, (novoValor, valorAntigo) => {
  console.log(`Busca mudou de "${valorAntigo}" para "${novoValor}"`)
  // aqui poderíamos chamar uma API, por exemplo
})
</script>

Uma boa regra prática: se você está apenas transformando um dado em outro dado (formatar um preço, filtrar uma lista, somar valores), use computed. Se você precisa executar uma ação (chamar uma API, mostrar uma notificação, gravar em algum lugar), use watch.

Composables: reaproveitando lógica entre componentes

A grande vantagem prática da Composition API é que, como o código não precisa mais estar preso dentro das seções fixas de um componente (data, methods etc.), você pode extrair um pedaço de lógica reativa para uma função JavaScript comum e reutilizá-la em vários componentes diferentes. Essas funções são chamadas de composables, e por convenção começam com use. Por exemplo, um composable para controlar um contador: 

// useContador.js
import { ref } from 'vue'

export function useContador(valorInicial = 0) {
  const contador = ref(valorInicial)

  function incrementar() {
    contador.value++
  }

  function decrementar() {
    contador.value--
  }

  return { contador, incrementar, decrementar }
}

E, em qualquer componente que precise dessa mesma lógica, basta importar e chamar: 

<script setup>
import { useContador } from './useContador.js'

const { contador, incrementar, decrementar } = useContador(10)
</script>

<template>
  <button @click="decrementar">-</button>
  {{ contador }}
  <button @click="incrementar">+</button>
</template>

Repare que useContador é apenas uma função JavaScript normal — nada de mágico além do fato de usar ref internamente. Esse é o real ganho da Composition API sobre a Options API: lógica reativa organizada e reutilizável, sem precisar de padrões mais complexos e menos diretos que o Vue 2 usava para tentar resolver o mesmo problema.

Dica Composables são um ótimo lugar para colocar qualquer lógica que se repete entre componentes: buscar dados de uma API, controlar um formulário, escutar o tamanho da janela, controlar um cronômetro. Se você perceber que está copiando e colando o mesmo bloco de ref/watch/computed em dois componentes diferentes, esse é o sinal de que vale a pena extrair um composable.

Resumo

  • A Composition API organiza o código por assunto/funcionalidade, enquanto a Options API organiza por tipo (data, methods, computed).
  • Use ref() como padrão; reserve reactive() para casos específicos, lembrando que desestruturar um reactive quebra a reatividade das propriedades extraídas.
  • computed cria um valor derivado com cache automático; use para transformar dados sem efeitos colaterais.
  • watch reage a mudanças para executar ações (chamadas de API, logs, gravações); use quando precisar de um efeito colateral, não de um novo valor.
  • Composables são funções (prefixadas com use) que agrupam lógica reativa reutilizável entre vários componentes.
