1. Fundamentos & Lógica

Tomando decisões: if/else

Aprenda a fazer o computador escolher um caminho diferente dependendo da situação.

Analogia Pense num guarda-chuva na porta de casa. Toda manhã você segue uma regrinha mental: "se estiver chovendo, eu levo o guarda-chuva; senão, eu deixo ele em casa". Você não leva o guarda-chuva sempre, e também não deixa de levar sempre — a decisão depende de uma condição (está chovendo ou não) que você checa antes de agir. Um if/else no código é exatamente essa regrinha, só que escrita de um jeito que o computador consegue seguir.

A estrutura básica do if

Na lição anterior você aprendeu os operadores de comparação (===, >, < etc.) e os lógicos (&&, ||). Eles existem justamente para serem usados dentro de um if: a condição entre parênteses é sempre algo que resulta em true ou false, e o bloco entre chaves { } só executa se o resultado for true. 

let estaChovendo = true;

if (estaChovendo) {
  console.log("Leve o guarda-chuva!");
}
// Como a condição é "true", essa linha é executada.

Quando você quer que algo aconteça no caso contrário, usa else ("senão"): 

let idade = 16;

if (idade >= 18) {
  console.log("Pode tirar carteira de motorista.");
} else {
  console.log("Ainda não pode tirar carteira.");
}
// Como 16 não é >= 18, a condição é false, então executa o bloco do "else".

Encadeando várias condições com else if

Quando existem mais de duas possibilidades, encadeamos com else if. O JavaScript testa as condições em ordem, de cima para baixo, e executa apenas o primeiro bloco cuja condição seja verdadeira — os demais são ignorados, mesmo que também fossem verdadeiros. 

let nota = 7;

if (nota >= 9) {
  console.log("Conceito A");
} else if (nota >= 7) {
  console.log("Conceito B");
} else if (nota >= 5) {
  console.log("Conceito C");
} else {
  console.log("Reprovado");
}
// nota = 7 não é >= 9, então pula.
// nota = 7 é >= 7, então imprime "Conceito B" e para por aí — não chega a checar as próximas.
Atenção A ordem das condições importa muito. Se no exemplo acima a gente tivesse escrito primeiro nota >= 5 e só depois nota >= 9, um aluno com nota 10 cairia na primeira condição (10 é maior que 5) e nunca chegaria a testar se também era maior que 9. Regra prática: coloque as condições mais restritivas (mais difíceis de satisfazer) primeiro.

Comparando com objetos: o switch

Quando você tem muitas condições comparando a mesma variável com valores exatos diferentes, existe uma alternativa que costuma ficar mais legível que uma cadeia longa de else if: o switch. 

let diaDaSemana = 3;
let nome;

switch (diaDaSemana) {
  case 1:
    nome = "Domingo";
    break;
  case 2:
    nome = "Segunda-feira";
    break;
  case 3:
    nome = "Terça-feira";
    break;
  default:
    nome = "Dia inválido";
}

console.log(nome); // Terça-feira

Cada case representa um valor possível, e o break é essencial: ele diz "pare aqui, não continue testando os próximos casos". Se você esquecer o break, o código continua executando os casos seguintes mesmo depois de já ter encontrado uma correspondência — um erro clássico chamado de "fall-through" (passar direto). O default funciona como o else final, cobrindo qualquer valor que não bateu com nenhum case.

O operador ternário: um if/else resumido em uma linha

Quando a decisão é simples (só decidir entre dois valores para atribuir a uma variável), existe uma forma curta chamada operador ternário: condição ? valorSeVerdadeiro : valorSeFalso. 

let idade = 20;

// Com if/else:
let status;
if (idade >= 18) {
  status = "maior de idade";
} else {
  status = "menor de idade";
}

// A mesma coisa, com ternário:
let status2 = idade >= 18 ? "maior de idade" : "menor de idade";

console.log(status2); // maior de idade

O ternário não substitui o if/else em todos os casos — ele é ótimo para decisões simples de uma linha, mas fica difícil de ler se você tentar encadear muitos deles. Use-o com moderação.

Dica Uma pegadinha comum: em JavaScript, valores como 0, "" (texto vazio), null, undefined e NaN são tratados como "falsos" quando usados numa condição, mesmo sem serem exatamente false. Por exemplo, if (quantidade) vai entrar no bloco do else se quantidade for 0. Preste atenção nisso ao testar números que podem legitimamente ser zero.

Pensando em árvore de decisão

Uma forma útil de planejar um if/else complexo antes de escrever código é desenhar (no papel mesmo) uma árvore de decisão: cada pergunta gera dois ou mais ramos, e cada ramo leva a uma ação ou a outra pergunta. Por exemplo, para decidir o valor do frete de uma compra: "o valor da compra é maior que R$200? Se sim, frete grátis. Se não, é para a mesma cidade? Se sim, R$10. Se não, R$25." Traduzir essa árvore para código já fica quase automático depois que ela está clara na sua cabeça — e isso é uma técnica que vamos revisitar na última lição desta trilha, sobre como pensar como programador.

Resumo

  • if (condição) { ... } executa um bloco só quando a condição é verdadeira; else cobre o caso contrário.
  • else if encadeia várias condições, e apenas a primeira verdadeira é executada.
  • A ordem das condições importa: coloque as mais restritivas primeiro.
  • switch é uma alternativa legível quando você compara a mesma variável com vários valores exatos — não esqueça o break.
  • O operador ternário (condição ? a : b) resume um if/else simples em uma linha.
  • Valores como 0, texto vazio e null contam como "falso" em uma condição, mesmo sem ser false.
