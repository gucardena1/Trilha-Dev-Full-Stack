1. Fundamentos & Lógica

Funções

Aprenda a empacotar um pedaço de código em um bloco reutilizável, que você pode chamar sempre que precisar.

Analogia Pense numa função como uma receita de bolo escrita num cartão de receitas. A receita tem um nome ("Bolo de Chocolate"), uma lista de ingredientes que você fornece (ovos, farinha, chocolate — os "ingredientes" da receita são o que chamamos de parâmetros) e um resultado final (o bolo pronto — o que chamamos de retorno). Uma vez que a receita está escrita, você não precisa reexplicar o passo a passo toda vez que quiser fazer um bolo — só precisa dizer "faça essa receita, com esses ingredientes" e ela sabe o que fazer. Uma função no código funciona exatamente assim: um bloco de instruções com nome, que você "chama" (executa) sempre que precisar, passando os ingredientes (dados) que ela precisa para funcionar.

Por que usar funções?

Imagine que, em vários pontos do seu programa, você precisa calcular o preço final de uma compra somando o frete. Sem funções, você copiaria e colaria a mesma conta em cada lugar que precisar dela. Isso é arriscado: se um dia a regra do frete mudar, você vai precisar caçar e corrigir cada cópia espalhada pelo código — e é fácil esquecer alguma. Com uma função, você escreve a lógica uma única vez, e todos os lugares que precisam dela apenas a "chamam". Se a regra mudar, você corrige em um só lugar.

Declarando uma função

function calcularPrecoFinal(preco, frete) {
  const total = preco + frete;
  return total;
}

// "Chamando" (executando) a função, passando valores reais:
const precoDaCompra = calcularPrecoFinal(100, 15);
console.log(precoDaCompra); // 115

const precoDeOutraCompra = calcularPrecoFinal(50, 0);
console.log(precoDeOutraCompra); // 50

Vamos destrinchar essa sintaxe: function é a palavra que anuncia "estou criando uma função"; calcularPrecoFinal é o nome que você escolheu (assim como o nome de uma receita); dentro dos parênteses, preco e frete são os parâmetros — os "ingredientes" que a função espera receber para funcionar; o bloco entre chaves { } é o corpo da função, onde a lógica acontece; e a palavra return devolve um valor para quem chamou a função — é o "bolo pronto" saindo do forno.

Dica Escolha nomes de função que descrevam claramente o que ela faz, de preferência começando com um verbo: calcularTotal, validarEmail, formatarData. Um bom nome de função é praticamente uma documentação — quem lê o código entende o que ela faz sem precisar abrir o corpo dela.

Parâmetros vs. argumentos

Existe uma diferença técnica pequena, mas útil de saber: parâmetros são os nomes que aparecem na declaração da função (preco e frete no exemplo acima) — são como "variáveis vazias" esperando um valor. Argumentos são os valores reais que você passa quando chama a função (100 e 15). Na prática, muita gente usa os dois termos como sinônimos no dia a dia, mas é bom reconhecer a diferença quando aparecer em alguma documentação.

Funções sem retorno

Nem toda função precisa devolver um valor com return. Algumas só executam uma ação, como exibir algo na tela: 

function saudar(nome) {
  console.log(`Olá, ${nome}! Seja bem-vindo.`);
  // sem "return" — essa função só executa uma ação, não devolve nada
}

saudar("Carlos"); // Olá, Carlos! Seja bem-vindo.
saudar("Marina"); // Olá, Marina! Seja bem-vindo.

Quando uma função não tem return explícito, o JavaScript considera que ela devolve undefined por padrão. Isso é importante saber: se você tentar guardar o resultado de uma função sem retorno numa variável, essa variável vai valer undefined.

Funções são reutilizáveis com valores diferentes

O grande poder de uma função é que ela funciona como um "molde": você define a lógica uma vez, com nomes genéricos (os parâmetros), e depois reaproveita esse molde quantas vezes quiser, com valores diferentes cada vez: 

function ehMaiorDeIdade(idade) {
  return idade >= 18;
}

console.log(ehMaiorDeIdade(20)); // true
console.log(ehMaiorDeIdade(15)); // false
console.log(ehMaiorDeIdade(18)); // true

Repare que a mesma função ehMaiorDeIdade deu respostas diferentes para entradas diferentes — isso é o comportamento esperado e desejado. A função não "decora" um resultado fixo, ela recalcula toda vez que é chamada, baseada no argumento que recebeu.

Arrow functions: uma sintaxe mais curta

Além da forma tradicional com a palavra function, o JavaScript moderno oferece uma sintaxe mais enxuta chamada arrow function (função seta), muito comum em código real: 

// Forma tradicional
function somar(a, b) {
  return a + b;
}

// Arrow function equivalente
const somar2 = (a, b) => {
  return a + b;
};

// Se o corpo é só um "return", pode ficar ainda mais curto:
const somar3 = (a, b) => a + b;

console.log(somar(2, 3));  // 5
console.log(somar2(2, 3)); // 5
console.log(somar3(2, 3)); // 5

As três formas acima fazem exatamente a mesma coisa. À medida que você avançar na trilha (principalmente na parte de JavaScript "de verdade"), vai ver arrow functions o tempo todo — por enquanto, o importante é reconhecer que => significa "isto é uma função", só que escrita de forma mais compacta.

Atenção Uma função só "faz alguma coisa" quando é chamada (com parênteses no final, como saudar("Carlos")). Escrever apenas saudar sem os parênteses não executa nada — apenas se refere à função em si, sem rodá-la. Esse é um erro comum: esquecer os parênteses e ficar sem entender por que "nada aconteceu".

Escopo: onde uma variável "existe"

Uma variável criada dentro de uma função só existe dentro dela — isso se chama escopo local. Fora da função, essa variável não existe e tentar usá-la gera erro: 

function calcularDobro(numero) {
  const resultado = numero * 2; // "resultado" só existe aqui dentro
  return resultado;
}

console.log(calcularDobro(5)); // 10
// console.log(resultado); // ERRO: "resultado" não existe fora da função

Esse isolamento é uma característica boa, não uma limitação: ele garante que uma variável criada dentro de uma função não vá "vazar" e bagunçar outra parte do código sem querer. Cada função tem seu próprio espaço de trabalho.

Resumo

  • Uma função empacota um bloco de código reutilizável, evitando repetir a mesma lógica em vários lugares.
  • Parâmetros são os "ingredientes" que a função recebe; return devolve um resultado para quem a chamou.
  • Uma função só executa quando é chamada com parênteses, como nomeDaFuncao(valor).
  • Funções podem não ter return, quando servem apenas para executar uma ação.
  • Arrow functions (=>) são uma forma mais curta de escrever funções, muito comuns em JavaScript moderno.
  • Variáveis criadas dentro de uma função têm escopo local: só existem dentro dela.
