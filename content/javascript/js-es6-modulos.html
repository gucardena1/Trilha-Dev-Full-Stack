3. JavaScript

ES6+ e módulos

O JavaScript moderno: recursos que deixam o código mais curto, mais claro, e a forma de organizar projetos em vários arquivos.

O que é "ES6+"?

ES6 (ECMAScript 2015) foi uma atualização enorme na linguagem JavaScript, lançada em 2015, que trouxe dezenas de recursos novos. "ES6+" é o jeito informal de dizer "ES6 e tudo que veio depois" — porque desde então o JavaScript recebe atualizações anuais. Praticamente todo código JavaScript escrito hoje usa esses recursos, então vale a pena aprendê-los bem cedo.

Analogia Se o JavaScript "clássico" (antes de 2015) é como escrever uma carta à mão, o JavaScript moderno é como usar um processador de texto: você ainda escreve as mesmas ideias, mas com atalhos, autocompletar e ferramentas que economizam tempo e reduzem erros de digitação.

let e const vs. var

Você já viu let e const nas lições anteriores. Agora vamos entender por que eles substituíram o antigo var. A diferença principal está no escopo — ou seja, em que "área" do código aquela variável existe e pode ser usada.

  • var tem escopo de função: ela "vaza" para fora de blocos if e for.
  • let e const têm escopo de bloco: existem só dentro das chaves { } onde foram criadas.
if (true) {
  var comVar = "eu vazo";
  let comLet = "eu fico aqui dentro";
}

console.log(comVar);  // "eu vazo" — funciona, mas é confuso
console.log(comLet);  // erro! comLet não existe fora do bloco
Pegadinha comum Um clássico problema de entrevista e de bugs reais: um loop com var dentro de um setTimeout. Como var não respeita o escopo do bloco do for, todas as funções acabam compartilhando a mesma variável i, que no final do loop já valerá 3: 
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // imprime 3, 3, 3 — não 0, 1, 2!
  }, 100);
}

// Trocando var por let, cada repetição do loop
// ganha sua PRÓPRIA cópia de i:
for (let j = 0; j < 3; j++) {
  setTimeout(function () {
    console.log(j); // imprime 0, 1, 2, como esperado
  }, 100);
}
Regra prática: use const por padrão, e só troque para let quando o valor realmente precisar mudar. Nunca use var em código novo.

Arrow functions: uma forma mais curta de escrever funções

As arrow functions (funções de seta) são uma sintaxe mais enxuta para escrever funções, muito usadas em callbacks curtos: 

// Forma tradicional
function dobrar(numero) {
  return numero * 2;
}

// Arrow function equivalente
const dobrar2 = (numero) => {
  return numero * 2;
};

// Se o corpo é só um "return", pode ficar numa linha só
const dobrar3 = (numero) => numero * 2;

// Com um único parâmetro, os parênteses são opcionais
const dobrar4 = numero => numero * 2;

Além de mais curtas, arrow functions têm uma diferença importante no comportamento do this — vamos ver isso com calma na próxima lição, sobre closures e this.

Template literals: montando textos com variáveis

Antes, para juntar texto com variáveis, usávamos o operador +, o que ficava confuso com muitas variáveis. Os template literals usam crase (`) em vez de aspas, e permitem inserir variáveis diretamente com ${...}: 

const nome = "Marina";
const idade = 28;

// Forma antiga
const antiga = "Olá, " + nome + "! Você tem " + idade + " anos.";

// Template literal
const moderna = `Olá, ${nome}! Você tem ${idade} anos.`;

// Também suportam múltiplas linhas sem precisar de \n
const mensagem = `Linha um
Linha dois`;

Destructuring: "desempacotando" arrays e objetos

Destructuring permite extrair valores de dentro de arrays ou objetos e colocá-los direto em variáveis, sem precisar acessar posição por posição ou propriedade por propriedade: 

// Destructuring de objeto
const usuario = { nome: "Ana", idade: 30, cidade: "Recife" };
const { nome, idade } = usuario;
console.log(nome, idade); // "Ana" 30

// Destructuring de array
const cores = ["vermelho", "verde", "azul"];
const [primeira, segunda] = cores;
console.log(primeira, segunda); // "vermelho" "verde"

// Muito comum em parâmetros de função
function mostrarPerfil({ nome, cidade }) {
  console.log(`${nome} mora em ${cidade}`);
}
mostrarPerfil(usuario); // "Ana mora em Recife"

Spread e rest: os três pontinhos (...) com dois significados

O operador de três pontos ... muda de comportamento dependendo de onde é usado. Como spread ("espalhar"), ele expande um array ou objeto: 

const numeros = [1, 2, 3];
const maisNumeros = [...numeros, 4, 5]; // [1, 2, 3, 4, 5]

const dadosBasicos = { nome: "Ana", idade: 30 };
const dadosCompletos = { ...dadosBasicos, cidade: "Recife" };
// { nome: "Ana", idade: 30, cidade: "Recife" }

Como rest ("restante"), ele faz o oposto: agrupa vários argumentos soltos dentro de um único array: 

function somarTudo(...numeros) {
  return numeros.reduce((total, atual) => total + atual, 0);
}

somarTudo(1, 2, 3, 4); // 10 — funciona com qualquer quantidade de argumentos
Dica Uma forma fácil de lembrar a diferença: se o ... aparece do lado direito (dentro de um array/objeto que está sendo criado, ou numa chamada de função), ele é spread — está "espalhando" algo que já existe. Se aparece do lado esquerdo (nos parâmetros de uma função), ele é rest — está "juntando" vários valores soltos.

Módulos: dividindo o código em vários arquivos

Conforme um projeto cresce, colocar tudo num único arquivo .js vira uma bagunça. Módulos permitem dividir o código em arquivos separados, cada um exportando o que quer disponibilizar e importando o que precisa de outros arquivos. 

// arquivo: matematica.js
export function somar(a, b) {
  return a + b;
}

export const PI = 3.14159;

// exportação "default": só pode haver uma por arquivo
export default function multiplicar(a, b) {
  return a * b;
}
// arquivo: main.js
import multiplicar, { somar, PI } from "./matematica.js";

console.log(somar(2, 3));       // 5
console.log(multiplicar(2, 3)); // 6
console.log(PI);                // 3.14159

Para usar módulos direto no navegador, é preciso avisar o HTML que aquele script é um módulo: 

<script type="module" src="main.js"></script>
Pegadinha comum Scripts com type="module" só funcionam servidos por um servidor web (mesmo local, como o "Live Server" do VS Code) — abrir o arquivo direto com "arquivo:///" no navegador costuma dar erro de CORS. Isso é uma regra de segurança do navegador, não um bug do seu código.

npm em uma frase

npm (Node Package Manager) é a loja de aplicativos do mundo JavaScript: um repositório gigante de códigos prontos (chamados de "pacotes" ou "bibliotecas") que qualquer pessoa pode instalar no seu projeto com um comando como npm install nome-do-pacote, evitando reescrever do zero coisas que outras pessoas já resolveram bem — desde formatação de datas até frameworks inteiros como Vue.

Resumo

  • let/const têm escopo de bloco e evitam os bugs de "vazamento" que o var causa, especialmente em loops.
  • Arrow functions (=>) são uma sintaxe mais curta para funções, muito usadas em callbacks.
  • Template literals (crase + ${...}) facilitam montar textos com variáveis.
  • Destructuring extrai valores de objetos e arrays direto para variáveis.
  • Spread (...) espalha valores de um array/objeto; rest agrupa vários argumentos soltos num array.
  • Módulos (import/export) dividem o código em arquivos organizados; npm é a "loja" de onde vêm pacotes prontos para usar.
