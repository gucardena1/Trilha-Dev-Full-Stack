3. JavaScript

Eventos, Promises e async/await

Como o JavaScript lida com o tempo: coisas que acontecem quando o usuário interage, e coisas que demoram para responder, como buscar dados na internet.

Eventos do DOM em profundidade

Na lição anterior você já usou addEventListener para reagir a um clique. Mas existem dezenas de eventos diferentes, e entender como eles se comportam é essencial para construir interfaces que funcionam bem.

  • click — o usuário clicou no elemento
  • input — o valor de um campo de formulário mudou (a cada tecla)
  • submit — um formulário foi enviado
  • keydown / keyup — uma tecla foi pressionada ou solta
  • mouseover / mouseout — o mouse entrou ou saiu de cima do elemento
  • load — um recurso (página, imagem) terminou de carregar

Quando um evento acontece, a função que você registrou recebe um objeto de evento, geralmente chamado de event ou e, que carrega informações sobre o que aconteceu:

const campo = document.querySelector("#email");

campo.addEventListener("input", function (e) {
  console.log("Valor atual:", e.target.value);
});

e.target é o elemento que disparou o evento — muito útil quando você registra o mesmo listener em vários elementos ao mesmo tempo.

Formulários merecem atenção especial. Por padrão, enviar um formulário recarrega a página inteira — o que quase sempre não é o que você quer numa aplicação moderna:

const form = document.querySelector("#form-login");

form.addEventListener("submit", function (e) {
  e.preventDefault(); // impede o recarregamento da página
  console.log("Formulário enviado sem recarregar!");
});
Dica e.preventDefault() é uma das linhas mais digitadas no JavaScript do mundo real. Ela cancela o "comportamento padrão" do navegador para aquele evento (recarregar a página num submit, seguir um link num clique, etc.), deixando você no controle total do que acontece.

Callbacks: passar uma função para outra função

Um callback é simplesmente uma função que você passa como argumento para outra função, para que ela seja "chamada de volta" em algum momento — como no próprio addEventListener, que recebe a função a ser executada quando o evento acontecer. 

function processar(numero, callback) {
  const resultado = numero * 2;
  callback(resultado);
}

processar(5, function (resultado) {
  console.log("O resultado é:", resultado); // "O resultado é: 10"
});

Callbacks são a base de tudo assíncrono em JavaScript, mas usados em excesso e encadeados uns dentro dos outros, criam um problema conhecido como "callback hell" (inferno de callbacks): código que cresce para o lado, cada vez mais difícil de ler. As Promises, que veremos a seguir, existem justamente para resolver isso.

Por que existe código assíncrono?

JavaScript executa código de forma síncrona por padrão: uma linha de cada vez, na ordem, e cada linha espera a anterior terminar. Isso funciona bem para contas e lógica simples. Mas existem operações que demoram um tempo imprevisível: buscar dados de um servidor na internet, ler um arquivo grande, esperar um temporizador.

Se o JavaScript travasse a página inteira esperando essas operações lentas terminarem, o navegador ficaria congelado — sem poder rolar a tela, clicar em nada, nem repintar a interface. Por isso o JavaScript trata operações demoradas de forma assíncrona: ele "dispara" a operação, continua executando o resto do código normalmente, e só volta a executar o que depende do resultado quando ele finalmente chega.

Analogia Pense numa padaria com sistema de senha. Você pede seu pão, recebe uma senha (o "ticket") na hora, e vai se sentar. Você não fica parado feito estátua na frente do balcão esperando o pão assar — você faz outras coisas (mexe no celular, conversa) e só volta quando chamam sua senha. A senha é a Promise: uma promessa de que, no futuro, você vai receber alguma coisa (o pão) ou vai ser avisado que deu errado (acabou a farinha).

Promises: representando um resultado futuro

Uma Promise é um objeto que representa o resultado de uma operação assíncrona que ainda não terminou, mas vai terminar — com sucesso ou com falha. Ela tem três estados possíveis: pending (pendente, ainda esperando), fulfilled (cumprida, deu certo) ou rejected (rejeitada, deu erro). 

const promessaDoPao = new Promise(function (resolve, reject) {
  const temFarinha = true;

  setTimeout(function () {
    if (temFarinha) {
      resolve("Pão quentinho!"); // deu certo
    } else {
      reject("Acabou a farinha."); // deu errado
    }
  }, 2000); // simula 2 segundos de espera
});

promessaDoPao
  .then(function (resultado) {
    console.log("Sucesso:", resultado);
  })
  .catch(function (erro) {
    console.log("Erro:", erro);
  });

.then() registra o que fazer quando a Promise é cumprida, e .catch() registra o que fazer quando ela é rejeitada. Você geralmente não vai criar Promises do zero com frequência — na prática, você vai consumir Promises que outras funções (como o fetch) já devolvem prontas.

fetch: buscando dados de verdade na internet

fetch é a função nativa do navegador para fazer requisições HTTP — ou seja, pedir dados para um servidor. Ela devolve uma Promise: 

fetch("https://api.exemplo.com/usuarios")
  .then(function (resposta) {
    return resposta.json(); // converte a resposta em objeto JavaScript
  })
  .then(function (usuarios) {
    console.log(usuarios); // a lista de usuários, já pronta para usar
  })
  .catch(function (erro) {
    console.log("Deu erro na requisição:", erro);
  });

async/await: escrevendo código assíncrono como se fosse síncrono

Encadear vários .then() ainda pode ficar confuso quando há muitos passos. O async/await é uma forma mais legível de trabalhar com Promises: ele deixa o código assíncrono com a cara de código síncrono, de cima para baixo, sem perder o comportamento de não travar a página. 

async function buscarUsuarios() {
  try {
    const resposta = await fetch("https://api.exemplo.com/usuarios");
    const usuarios = await resposta.json();
    console.log(usuarios);
  } catch (erro) {
    console.log("Deu erro na requisição:", erro);
  }
}

buscarUsuarios();

Duas regras simples:

  • A palavra await só pode ser usada dentro de uma função marcada com async.
  • await "pausa" a execução daquela função até a Promise resolver, sem travar o restante da página.

O bloco try/catch substitui o .catch(): tudo que der erro dentro do try é capturado no catch, incluindo falhas de rede ou de conversão de dados.

Exemplo prático: buscando dados de uma API pública

async function buscarPiada() {
  const status = document.querySelector("#status");
  status.textContent = "Carregando...";

  try {
    const resposta = await fetch("https://api.exemplo.com/piada-aleatoria");
    const dados = await resposta.json();
    status.textContent = dados.piada;
  } catch (erro) {
    status.textContent = "Não foi possível carregar a piada agora.";
  }
}

document.querySelector("#btn-piada").addEventListener("click", buscarPiada);

Repare como o código conta uma história linear: mostra "Carregando...", tenta buscar, e trata tanto o sucesso quanto o erro — tudo isso enquanto o resto da página continua funcionando normalmente.

Pegadinha comum Esquecer o await antes de uma chamada assíncrona é um dos erros mais comuns em quem está aprendendo. Sem ele, você não recebe o resultado — recebe a própria Promise, ainda pendente. Se o console.log mostrar algo como Promise { <pending> }, é sinal de que faltou um await (ou um .then()).

Resumo

  • Eventos do DOM carregam informações em e.target, e e.preventDefault() cancela o comportamento padrão do navegador.
  • Callback é uma função passada para outra função ser executada mais tarde; abusar deles cria o "callback hell".
  • Código assíncrono existe para que operações demoradas (como buscar dados) não travem a página inteira.
  • Uma Promise representa um resultado futuro: pendente, cumprida (.then()) ou rejeitada (.catch()).
  • fetch() faz requisições HTTP e devolve uma Promise com a resposta.
  • async/await deixa código assíncrono mais legível, escrito "de cima para baixo", usando try/catch para tratar erros.
