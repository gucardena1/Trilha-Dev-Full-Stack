6. PHP & Laravel

Middleware, autenticação e validação

As últimas camadas de proteção antes de um pedido chegar ao seu Controller: quem pode entrar e o que pode ser enviado.

Analogia Middleware é como o segurança na portaria de um prédio. Antes de qualquer visitante chegar ao apartamento (o Controller), ele passa pela portaria, e o segurança decide: "essa pessoa está na lista de moradores autorizados? Ela apresentou identidade? Ok, pode subir" — ou então "não, você não pode entrar, volte outra hora". O segurança não sabe (nem precisa saber) o que acontece dentro de cada apartamento; ele só controla o acesso na entrada. Um middleware no Laravel faz exatamente isso com cada requisição: intercepta antes dela chegar ao Controller e decide se ela pode passar, é redirecionada, ou é bloqueada.

O que é middleware

Um middleware é uma camada de código que roda antes (e às vezes depois) de uma requisição chegar ao Controller. Ele pode inspecionar a requisição, tomar uma decisão, e escolher entre deixar a requisição continuar seu caminho normal ou interrompê-la (por exemplo, redirecionando para a página de login). Vários middlewares podem ser encadeados, como vários seguranças em portarias diferentes dentro do mesmo condomínio, cada um checando uma coisa diferente. 

<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;

class VerificarIdade
{
    public function handle(Request $request, Closure $next)
    {
        if ($request->input('idade') < 18) {
            return redirect('/acesso-negado');
        }

        // Deixa a requisição seguir para o próximo passo (outro middleware ou o Controller)
        return $next($request);
    }
}

A chamada $next($request) é o momento em que o "segurança" libera a passagem: se essa linha não for executada, a requisição nunca chega ao Controller. Um middleware é registrado em app/Http/Kernel.php e depois aplicado a rotas específicas: 

Route::get('/area-restrita', [AreaController::class, 'index'])
    ->middleware('verificar.idade');
Dica O Laravel já vem com middlewares prontos para as necessidades mais comuns, como auth (exige usuário logado) e guest (exige que o usuário NÃO esteja logado, útil na própria página de login). Você raramente precisa escrever middleware do zero para tarefas básicas de autenticação.

Autenticação básica no Laravel

Autenticação é o processo de confirmar "quem é o usuário" (diferente de autorização, que é decidir "o que esse usuário pode fazer"). O Laravel tem um sistema de autenticação embutido que já cuida de hashing de senha, sessões e proteção contra ataques comuns, sem você precisar implementar nada disso manualmente. 

<?php

use Illuminate\Support\Facades\Auth;

class LoginController extends Controller
{
    public function login(Request $request)
    {
        $credenciais = $request->only('email', 'password');

        if (Auth::attempt($credenciais)) {
            // Login bem-sucedido: o Laravel já cria a sessão do usuário
            $request->session()->regenerate();
            return redirect('/dashboard');
        }

        return back()->withErrors(['email' => 'Credenciais inválidas']);
    }

    public function logout(Request $request)
    {
        Auth::logout();
        return redirect('/');
    }
}

Auth::attempt() recebe email e senha, verifica se existe um usuário com esse email no banco e compara a senha informada com o hash salvo (nunca a senha salva em texto puro — o Laravel usa hashing seguro por padrão). Se bater, ele autentica o usuário e guarda essa informação na sessão. Depois disso, você pode proteger rotas inteiras com o middleware auth: 

Route::get('/dashboard', [DashboardController::class, 'index'])
    ->middleware('auth');

Com isso, qualquer visitante não autenticado que tentar acessar /dashboard é automaticamente redirecionado para a tela de login, sem que o Controller DashboardController precise verificar isso manualmente — o "segurança da portaria" já resolveu antes de chegar lá.

Validação de formulários e requisições

Antes de salvar qualquer dado enviado por um usuário — um formulário de cadastro, por exemplo — é essencial validar se os dados estão corretos: campos obrigatórios preenchidos, formato de e-mail válido, senha com tamanho mínimo, etc. O Laravel oferece uma forma direta de validar dentro do próprio Controller: 

<?php

public function store(Request $request)
{
    $validado = $request->validate([
        'nome' => 'required|string|max:255',
        'email' => 'required|email|unique:users,email',
        'preco' => 'required|numeric|min:0',
    ]);

    Produto::create($validado);

    return redirect('/produtos')->with('sucesso', 'Produto criado!');
}

Se qualquer uma dessas regras falhar, o Laravel automaticamente interrompe a execução, redireciona de volta ao formulário e disponibiliza as mensagens de erro para a view exibir — tudo isso sem você escrever nenhum if manual. Na view Blade, basta exibir os erros: 

@if ($errors->any())
    <ul>
        @foreach ($errors->all() as $erro)
            <li>{{ $erro }}</li>
        @endforeach
    </ul>
@endif

Para validações mais complexas ou reutilizadas em vários lugares, o Laravel oferece as Form Requests — classes próprias que centralizam as regras de validação fora do Controller: 

php artisan make:request StoreProdutoRequest
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StoreProdutoRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true; // aqui você pode checar permissões específicas, se precisar
    }

    public function rules(): array
    {
        return [
            'nome' => 'required|string|max:255',
            'preco' => 'required|numeric|min:0',
        ];
    }
}
// No Controller, basta trocar Request por essa classe específica:
public function store(StoreProdutoRequest $request)
{
    // Se chegou até aqui, a validação já passou automaticamente
    Produto::create($request->validated());
    return redirect('/produtos');
}
Atenção Nunca confie apenas na validação feita no navegador (como o atributo required do HTML) — ela pode ser facilmente ignorada por quem sabe o que está fazendo. A validação de verdade, que protege seus dados, precisa acontecer sempre no servidor, dentro do Controller ou de uma Form Request, como mostrado acima. E lembre-se: assim como o mass assignment da lição anterior, validar os dados não substitui declarar $fillable no Model — as duas proteções trabalham juntas.

Juntando tudo

Com middleware, autenticação e validação, você fecha o ciclo básico de segurança de uma aplicação Laravel: o middleware controla quem pode acessar cada rota, a autenticação identifica quem é o usuário fazendo a requisição, e a validação garante que os dados enviados estão no formato esperado antes de qualquer coisa ser salva no banco. Essas três camadas, junto com tudo que você já viu sobre MVC, rotas, Blade, Eloquent e migrations, formam a base necessária para construir uma aplicação Laravel completa e segura do zero.

Resumo

  • Middleware intercepta a requisição antes do Controller, decidindo se ela pode continuar ou deve ser bloqueada/redirecionada.
  • $next($request) é o que libera a requisição para a próxima etapa dentro de um middleware.
  • O middleware auth, já pronto no Laravel, protege rotas exigindo usuário autenticado.
  • Auth::attempt() verifica credenciais e autentica o usuário, cuidando de sessão e hashing automaticamente.
  • $request->validate([...]) valida dados de formulário direto no Controller; Form Requests centralizam regras mais complexas.
  • Nunca confie só na validação do navegador — a validação real e obrigatória acontece no servidor.
