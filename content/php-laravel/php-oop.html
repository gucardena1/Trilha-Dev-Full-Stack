6. PHP & Laravel

Orientação a objetos em PHP

Classes, objetos, herança e interfaces — a forma de organizar código que sustenta todo o Laravel.

Analogia Uma classe é como a planta baixa de uma casa: um desenho técnico que descreve quantos quartos existem, onde ficam as janelas, qual o tamanho da garagem. A planta em si não é uma casa — você não pode morar num papel. Um objeto é a casa construída a partir dessa planta: uma casa de verdade, com endereço, com uma cor específica de tinta, com móveis dentro. Você pode construir várias casas (objetos) diferentes a partir da mesma planta (classe) — cada uma é independente das outras, mas todas seguem a mesma estrutura básica definida no desenho.

Por que orientação a objetos?

Até agora você viu PHP com variáveis, arrays e funções soltas — isso é chamado de estilo procedural. Funciona bem para scripts pequenos, mas em sistemas maiores fica difícil organizar tudo: dados e as funções que mexem neles ficam espalhados pelo código, sem uma relação clara. A orientação a objetos (OOP) resolve isso agrupando dados e comportamentos relacionados dentro de uma mesma estrutura: a classe. O Laravel, framework que você vai estudar nas próximas lições, é inteiramente construído em cima de orientação a objetos — então entender bem esses conceitos aqui vai tornar tudo o que vem depois muito mais fácil.

Classes e objetos na prática

Uma classe define duas coisas: propriedades (os dados que cada objeto vai guardar, como os "cômodos" da planta baixa) e métodos (as ações que o objeto pode realizar, como "abrir a porta" ou "ligar a luz"). Veja uma classe simples representando um produto: 

<?php
class Produto {
    // Propriedades: os dados que cada objeto (cada "casa") vai ter
    public string $nome;
    public float $preco;

    // Método construtor: roda automaticamente quando um objeto é criado
    public function __construct(string $nome, float $preco) {
        $this->nome = $nome;
        $this->preco = $preco;
    }

    // Método: uma ação que o objeto sabe fazer
    public function precoComDesconto(float $percentual): float {
        return $this->preco - ($this->preco * $percentual / 100);
    }
}

// Criando objetos (as "casas") a partir da classe (a "planta")
$produto1 = new Produto("Teclado", 150.0);
$produto2 = new Produto("Mouse", 60.0);

echo $produto1->nome; // "Teclado"
echo $produto1->precoComDesconto(10); // 135

// produto1 e produto2 são independentes: mudar um não afeta o outro
$produto2->preco = 55.0;

Repare na palavra-chave $this: dentro de um método, ela sempre se refere "ao objeto que está chamando esse método agora". É assim que o método precoComDesconto sabe qual preço usar — o preço do objeto específico que o chamou ($produto1 ou $produto2), e não um valor fixo.

Dica O construtor (__construct) é o método especial que roda automaticamente toda vez que você usa new NomeDaClasse(...). É o lugar ideal para "preencher" as propriedades iniciais do objeto, exatamente como preencher os dados básicos assim que a casa fica pronta.

Visibilidade: public, private e protected

PHP permite controlar quem pode acessar cada propriedade ou método de uma classe:

  • public — pode ser acessado de qualquer lugar, até de fora da classe.
  • private — só pode ser acessado de dentro da própria classe.
  • protected — acessível de dentro da classe e também das classes que herdam dela.
<?php
class ContaBancaria {
    private float $saldo = 0;

    public function depositar(float $valor): void {
        $this->saldo += $valor;
    }

    public function verSaldo(): float {
        return $this->saldo;
    }
}

$conta = new ContaBancaria();
$conta->depositar(100);
echo $conta->verSaldo(); // 100
// $conta->saldo = 999999; // Erro! saldo é private, não pode ser alterado direto

Essa proteção existe para evitar que o saldo seja alterado de qualquer jeito, sem passar pela lógica do método depositar. É como uma casa com uma porta trancada: só quem tem a "chave" (o método público) consegue mexer no que está protegido lá dentro.

Herança: reaproveitando uma planta baixa

Herança permite criar uma classe nova baseada em outra já existente, reaproveitando suas propriedades e métodos e podendo adicionar ou modificar comportamentos. É como pegar a planta baixa de uma casa padrão e fazer uma versão "de luxo" dela, mantendo a estrutura básica mas acrescentando cômodos extras. 

<?php
class Funcionario {
    public string $nome;
    protected float $salarioBase;

    public function __construct(string $nome, float $salarioBase) {
        $this->nome = $nome;
        $this->salarioBase = $salarioBase;
    }

    public function calcularSalario(): float {
        return $this->salarioBase;
    }
}

// Gerente "herda" tudo de Funcionario, usando extends
class Gerente extends Funcionario {
    private float $bonus;

    public function __construct(string $nome, float $salarioBase, float $bonus) {
        parent::__construct($nome, $salarioBase); // chama o construtor da classe "pai"
        $this->bonus = $bonus;
    }

    // Sobrescrevendo o método do "pai" com um comportamento próprio
    public function calcularSalario(): float {
        return $this->salarioBase + $this->bonus;
    }
}

$joao = new Funcionario("João", 3000);
$maria = new Gerente("Maria", 5000, 1500);

echo $joao->calcularSalario();  // 3000
echo $maria->calcularSalario(); // 6500

Gerente extends Funcionario significa "Gerente é um tipo de Funcionario, mas com algumas diferenças". A palavra parent:: deixa a classe filha chamar o comportamento original da classe pai, antes de completar o que for específico dela.

Interfaces: um contrato de comportamento

Uma interface não implementa nada — ela apenas promete que qualquer classe que a use vai ter certos métodos, com certos nomes. É como um contrato: "toda classe que assinar este contrato precisa ter um método calcularFrete()", sem dizer como esse cálculo deve ser feito internamente. 

<?php
interface Calculavel {
    public function calcularFrete(): float;
}

class EntregaPadrao implements Calculavel {
    public function calcularFrete(): float {
        return 15.0;
    }
}

class EntregaExpressa implements Calculavel {
    public function calcularFrete(): float {
        return 45.0;
    }
}

function mostrarFrete(Calculavel $entrega) {
    echo "Frete: R$ " . $entrega->calcularFrete();
}

mostrarFrete(new EntregaPadrao());   // Frete: R$ 15
mostrarFrete(new EntregaExpressa()); // Frete: R$ 45

A função mostrarFrete não precisa saber se recebeu uma entrega padrão ou expressa — ela só confia que, seja qual for o objeto, ele vai ter um método calcularFrete() porque implementa a interface Calculavel. Esse é o mesmo princípio usado o tempo todo dentro do Laravel, por exemplo quando o framework espera receber "qualquer coisa que saiba enviar um e-mail", sem se importar com qual serviço específico está por trás.

Atenção Um erro comum de iniciantes é confundir classe com objeto e achar que basta escrever a classe para "algo acontecer". Nada acontece até você criar um objeto com new NomeDaClasse(...) — a classe sozinha é só a planta, parada no papel, até alguém construir a casa.

Resumo

  • Classe é a "planta baixa" (estrutura); objeto é a "casa construída" (instância real) a partir dela.
  • Propriedades guardam dados; métodos definem ações que o objeto sabe realizar.
  • $this dentro de um método se refere ao próprio objeto que o chamou.
  • public, private e protected controlam quem pode acessar cada parte da classe.
  • Herança (extends) reaproveita estrutura de uma classe "pai" em uma classe "filha".
  • Interfaces (implements) definem um contrato de métodos que a classe promete implementar.
