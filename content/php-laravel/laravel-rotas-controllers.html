6. PHP & Laravel

Rotas, controllers e Blade

Colocando o MVC em prática: como uma URL vira código, e como esse código vira uma página de verdade.

Analogia Se o Laravel fosse um prédio, as rotas seriam a portaria com a lista de apartamentos: quando alguém chega dizendo "quero ir ao apartamento /produtos", a portaria consulta a lista e diz exatamente para qual andar e sala mandar essa pessoa — ou seja, qual Controller deve cuidar daquele pedido. O Controller, por sua vez, é como o morador daquele apartamento: recebe a visita, organiza o que for preciso, e chama a "sala de estar" (a View, escrita em Blade) para receber o visitante de forma apresentável.

Rotas: a porta de entrada de cada URL

Toda URL que existe num site Laravel precisa estar registrada em um arquivo de rotas — o mais comum é routes/web.php. Uma rota conecta um caminho de URL a uma ação: pode ser uma função anônima direta ou, o mais comum em projetos reais, um método de um Controller. 

<?php
use Illuminate\Support\Facades\Route;
use App\Http\Controllers\ProdutoController;

// Rota simples, direto no arquivo (só para testes rápidos)
Route::get('/ola', function () {
    return 'Olá, mundo!';
});

// Rota "de verdade", apontando para um Controller
Route::get('/produtos', [ProdutoController::class, 'index']);
Route::get('/produtos/{id}', [ProdutoController::class, 'show']);
Route::post('/produtos', [ProdutoController::class, 'store']);

Cada linha combina um verbo HTTP (get para visualizar uma página, post para enviar dados de um formulário, entre outros) com um caminho (a parte da URL depois do domínio) e o que deve acontecer quando essa combinação for acessada. O trecho {id} é um parâmetro de rota: uma parte variável da URL, como /produtos/7 ou /produtos/42, cujo valor (7 ou 42) é enviado automaticamente para o Controller.

Dica Para ver rapidamente todas as rotas registradas em um projeto, rode php artisan route:list no terminal. É uma das ferramentas mais úteis do dia a dia com Laravel.

Criando um Controller

Um Controller é apenas uma classe PHP comum, guardada em app/Http/Controllers, com métodos que respondem a cada rota. Você pode criar um novo controller pelo Artisan, sem precisar escrever a estrutura inicial manualmente: 

php artisan make:controller ProdutoController

Isso gera um arquivo app/Http/Controllers/ProdutoController.php já com a estrutura básica de classe pronta. Você então escreve os métodos que as rotas vão chamar: 

<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class ProdutoController extends Controller
{
    // Chamado pela rota GET /produtos
    public function index()
    {
        $produtos = [
            ['nome' => 'Teclado', 'preco' => 150],
            ['nome' => 'Mouse', 'preco' => 60],
        ];

        // Envia os dados para a view "produtos.index"
        return view('produtos.index', ['produtos' => $produtos]);
    }

    // Chamado pela rota GET /produtos/{id}
    public function show($id)
    {
        $produto = ['nome' => 'Teclado', 'preco' => 150];

        return view('produtos.show', ['produto' => $produto, 'id' => $id]);
    }
}

Repare como o Controller aqui é bem "magro": ele monta ou busca os dados e apenas os repassa para a view, sem escrever nenhum HTML diretamente. Isso é o Controller cumprindo seu papel de "garçom" — ele não cozinha (isso será tarefa do Model, na próxima lição) e não decora o prato (isso é tarefa da View).

Blade: o motor de templates do Laravel

Blade é a linguagem de views do Laravel. Os arquivos Blade ficam em resources/views e têm a extensão .blade.php. Ele permite escrever HTML normal e, quando precisar, inserir lógica PHP usando uma sintaxe mais limpa que o PHP puro dentro de tags. 

{{-- resources/views/produtos/index.blade.php --}}
<!doctype html>
<html>
<head>
    <title>Produtos</title>
</head>
<body>
    <h1>Nossos produtos</h1>

    <ul>
        @foreach ($produtos as $produto)
            <li>{{ $produto['nome'] }} — R$ {{ $produto['preco'] }}</li>
        @endforeach
    </ul>

    @if (count($produtos) === 0)
        <p>Nenhum produto cadastrado ainda.</p>
    @endif
</body>
</html>

A sintaxe do Blade tem algumas peças fundamentais que você vai usar o tempo todo:

  • {{ $variavel }} — exibe o valor de uma variável na tela, já protegido automaticamente contra ataques de injeção de HTML/JavaScript malicioso.
  • @if / @else / @endif — condicional, equivalente ao if do PHP puro.
  • @foreach / @endforeach — laço de repetição, equivalente ao foreach do PHP.
  • {{-- comentário --}} — comentário que não aparece nem no HTML final (diferente de um comentário HTML comum).

Layouts: reaproveitando estrutura entre páginas

Em vez de repetir o mesmo cabeçalho e rodapé em toda página, o Blade permite criar um "layout" base e apenas preencher o conteúdo que muda: 

{{-- resources/views/layouts/app.blade.php --}}
<!doctype html>
<html>
<head><title>Minha Loja</title></head>
<body>
    <header>Minha Loja</header>

    @yield('conteudo')

    <footer>© 2026 Minha Loja</footer>
</body>
</html>

{{-- resources/views/produtos/index.blade.php --}}
@extends('layouts.app')

@section('conteudo')
    <h1>Nossos produtos</h1>
    @foreach ($produtos as $produto)
        <p>{{ $produto['nome'] }}</p>
    @endforeach
@endsection

@extends diz "esta view usa aquele layout como base". @section('conteudo') define o que deve entrar exatamente no lugar onde o layout tem @yield('conteudo'). Isso evita duplicar cabeçalho, rodapé e menu em cada página do site.

Atenção Uma armadilha comum é colocar lógica de negócio complexa dentro da view Blade — por exemplo, cálculos pesados ou consultas ao banco de dados direto no arquivo .blade.php. A view deve ficar responsável apenas por exibir dados que já chegaram prontos do Controller (e do Model). Se você perceber muita lógica dentro de uma view, é sinal de que ela deveria estar no Controller ou no Model.

Resumo

  • Rotas conectam uma URL e um verbo HTTP a uma ação, geralmente um método de Controller.
  • Controllers são classes PHP em app/Http/Controllers que recebem a requisição, buscam dados e os enviam para uma view.
  • A função view() retorna uma view Blade, passando dados para ela usar.
  • Blade usa {{ }} para exibir valores, e diretivas como @if e @foreach para lógica.
  • @extends e @section/@yield permitem reaproveitar um layout comum entre várias páginas.
  • A view não deve conter lógica de negócio pesada — apenas exibir dados já prontos.
