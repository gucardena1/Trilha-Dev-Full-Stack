6. PHP & Laravel

Introdução ao Laravel e MVC

Por que quase ninguém escreve PHP "puro" em produção, e como o padrão MVC organiza um sistema inteiro.

Analogia Pense num restaurante organizado. O cliente faz um pedido ao garçom (Controller). O garçom não cozinha nada — ele só recebe o pedido, leva até a cozinha e depois traz o resultado de volta. Na cozinha (Model) é onde os ingredientes de verdade ficam guardados e onde a comida é realmente preparada — é lá que estão os dados e as regras de como prepará-los. E o prato que chega até a mesa, bonito e pronto para ser visto (View), é só a apresentação final: o cliente nunca vê a bagunça da cozinha, só o resultado já arrumado. Cada parte faz um trabalho e não se mistura com o trabalho da outra — é isso que faz o restaurante (e um sistema web) funcionar sem caos.

Por que usar um framework em vez de PHP puro?

Quando você escreve PHP puro (como nas duas lições anteriores), toda vez que quer construir uma funcionalidade — login de usuário, formulário com validação, conexão com banco de dados, proteção contra ataques comuns — você precisa escrever isso do zero. É como construir uma casa fabricando você mesmo cada tijolo, cano e fio elétrico. Funciona, mas é lento, repetitivo e fácil de errar.

Um framework é um conjunto de ferramentas, regras e estruturas prontas que resolvem os problemas mais comuns de um sistema web, para que você foque no que é específico do seu projeto. O Laravel é o framework PHP mais popular do mundo hoje. Ele já vem com: um jeito organizado de definir rotas (quais URLs existem no site), um sistema de banco de dados chamado Eloquent, um motor de templates chamado Blade, autenticação de usuários pronta, validação de formulários, proteção contra os ataques mais comuns, e muito mais — tudo isso pronto para usar, sem você precisar reinventar.

Usar um framework não é "trapacear" — é aproveitar o trabalho de milhares de desenvolvedores que já resolveram esses problemas antes, testaram exaustivamente e mantêm atualizado contra falhas de segurança. Praticamente todo sistema PHP profissional moderno é construído sobre algum framework, e o Laravel é hoje a escolha mais comum no mercado.

Dica Você não precisa saber PHP "avançado" para começar no Laravel, mas precisa estar confortável com o básico da linguagem e, principalmente, com orientação a objetos — classes, objetos, herança — porque o Laravel usa esses conceitos o tempo todo em sua estrutura interna.

O padrão MVC

MVC significa Model - View - Controller (Modelo - Visão - Controlador). É um padrão de arquitetura usado por praticamente todo framework web moderno (não só Laravel) para separar responsabilidades dentro do sistema. Voltando à analogia do restaurante:

  • Model (Cozinha) — representa os dados e as regras de negócio do sistema. É a camada que sabe como buscar, salvar e validar informações — por exemplo, uma classe Produto que sabe buscar todos os produtos no banco de dados. O Model não sabe nada sobre como essa informação vai ser exibida na tela.
  • View (Prato servido) — é a camada de apresentação: o HTML que o usuário efetivamente vê. No Laravel, as views são escritas usando o Blade (que você vai estudar na próxima lição). A view não decide regra nenhuma de negócio — ela só recebe dados prontos e os exibe.
  • Controller (Garçom) — recebe a requisição do usuário (por exemplo, "quero ver a página de produtos"), pede ao Model os dados necessários, e entrega esses dados para a View exibir. O Controller é o "meio de campo": ele coordena, mas não faz o trabalho pesado de nenhum dos outros dois.

Um exemplo simples do fluxo MVC

Imagine que um usuário acessa a URL /produtos no navegador. O fluxo dentro de um sistema Laravel seria mais ou menos assim: 

1. O navegador pede a URL /produtos
2. O Laravel consulta as ROTAS e descobre: essa URL pertence ao ProdutoController
3. O CONTROLLER (garçom) chama o MODEL para buscar os produtos:
   $produtos = Produto::all();
4. O MODEL (cozinha) consulta o banco de dados e devolve os dados
5. O CONTROLLER envia esses dados para a VIEW:
   return view('produtos.index', ['produtos' => $produtos]);
6. A VIEW (prato servido) monta o HTML final usando esses dados
7. O navegador recebe o HTML pronto e exibe a página ao usuário

Repare que cada peça só sabe fazer o que é seu papel. O Controller nunca escreve HTML. A View nunca faz consulta direta ao banco de dados. O Model nunca decide como algo vai aparecer na tela. Essa separação é o que torna sistemas grandes muito mais fáceis de manter — se você precisa mudar o visual da página, mexe só na View; se precisa mudar uma regra de negócio, mexe só no Model.

Atenção Um erro muito comum de quem está começando com Laravel é "misturar tudo": colocar lógica de banco de dados direto dentro da view, ou construir HTML dentro do controller. Isso funciona no curto prazo, mas quebra a organização do MVC e torna o código muito mais difícil de manter conforme o projeto cresce. Sempre que possível, mantenha cada responsabilidade na camada certa.

Instalando e conhecendo a estrutura de um projeto Laravel

Um projeto Laravel é criado através do Composer (o gerenciador de pacotes do PHP), com um comando como: 

composer create-project laravel/laravel meu-projeto
cd meu-projeto
php artisan serve

O comando php artisan serve sobe um servidor local para você testar o projeto no navegador. O Artisan é a ferramenta de linha de comando do Laravel — você vai usá-la bastante ao longo desta trilha para criar controllers, models, rodar migrations e muito mais. Dentro da estrutura de pastas de um projeto Laravel, as mais importantes para você neste momento são:

  • app/Models — onde ficam as classes Model (a "cozinha").
  • app/Http/Controllers — onde ficam os Controllers (os "garçons").
  • resources/views — onde ficam os arquivos Blade, as Views (os "pratos").
  • routes/web.php — onde as rotas (URLs) do site são definidas.

O que vem a seguir

Nas próximas lições você vai aprender, na prática, a criar rotas, controllers e views com Blade (a "cozinha" ganhando vida real com Models e Migrations, e depois com regras de segurança usando middleware e autenticação). Este conceito de MVC vai aparecer em quase tudo — vale a pena voltar aqui sempre que sentir que perdeu a visão geral de "quem faz o quê" dentro de um projeto Laravel.

Resumo

  • Um framework como o Laravel oferece soluções prontas e testadas para problemas comuns de sistemas web, evitando reinventar a roda.
  • MVC separa um sistema em três papéis: Model (dados e regras), View (apresentação) e Controller (coordenação).
  • O Controller nunca deve conter HTML; a View nunca deve consultar o banco de dados diretamente.
  • O Artisan é a ferramenta de linha de comando do Laravel, usada para criar arquivos e rodar tarefas do projeto.
  • As pastas principais de um projeto Laravel são app/Models, app/Http/Controllers, resources/views e routes/web.php.
